# Jade Service

## Overview

The Jade service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Jade exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Jade v3.5.0. Owner: Platform Team. This document describes configuration, endpoints, error codes, and troubleshooting for Jade.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_JADE_TIMEOUT_MS (default 3875)
- NIMBUS_JADE_MAX_RETRIES (default 6)
- NIMBUS_JADE_POOL_SIZE (default 28)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_JADE_TIMEOUT_MS affects request timeout behavior for Jade.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/jade/restart
- GET /api/v1/jade/status
- POST /api/v1/jade/cache/flush
Use POST /api/v1/jade/restart to restart the Jade service, GET /api/v1/jade/status to check health, and POST /api/v1/jade/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Jade service:
- ERR-1351: connection pool exhausted
- ERR-1352: upstream timeout exceeded
- ERR-1353: invalid authentication token
- ERR-1354: payload schema validation failed
When you see ERR-1351, the connection pool is exhausted; increase NIMBUS_JADE_POOL_SIZE. ERR-1352 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Jade service. If you observe connection drops or high latency, first check GET /api/v1/jade/status, then review recent error codes. Restart with `nimbusctl jade restart` or POST /api/v1/jade/restart. Persistent timeouts usually mean NIMBUS_JADE_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to Platform Team.
