# Slate Service

## Overview

The Slate service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Slate exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Slate v1.8.0. Owner: Data Team. This document describes configuration, endpoints, error codes, and troubleshooting for Slate.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_SLATE_TIMEOUT_MS (default 3450)
- NIMBUS_SLATE_MAX_RETRIES (default 5)
- NIMBUS_SLATE_POOL_SIZE (default 24)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_SLATE_TIMEOUT_MS affects request timeout behavior for Slate.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/slate/restart
- GET /api/v1/slate/status
- POST /api/v1/slate/cache/flush
Use POST /api/v1/slate/restart to restart the Slate service, GET /api/v1/slate/status to check health, and POST /api/v1/slate/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Slate service:
- ERR-1181: connection pool exhausted
- ERR-1182: upstream timeout exceeded
- ERR-1183: invalid authentication token
- ERR-1184: payload schema validation failed
When you see ERR-1181, the connection pool is exhausted; increase NIMBUS_SLATE_POOL_SIZE. ERR-1182 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Slate service. If you observe connection drops or high latency, first check GET /api/v1/slate/status, then review recent error codes. Restart with `nimbusctl slate restart` or POST /api/v1/slate/restart. Persistent timeouts usually mean NIMBUS_SLATE_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to Data Team.
