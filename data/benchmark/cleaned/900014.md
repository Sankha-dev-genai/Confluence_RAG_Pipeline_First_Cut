# Nimbus Service

## Overview

The Nimbus service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Nimbus exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Nimbus v2.3.0. Owner: Data Team. This document describes configuration, endpoints, error codes, and troubleshooting for Nimbus.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_NIMBUS_TIMEOUT_MS (default 3325)
- NIMBUS_NIMBUS_MAX_RETRIES (default 4)
- NIMBUS_NIMBUS_POOL_SIZE (default 36)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_NIMBUS_TIMEOUT_MS affects request timeout behavior for Nimbus.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/nimbus/restart
- GET /api/v1/nimbus/status
- POST /api/v1/nimbus/cache/flush
Use POST /api/v1/nimbus/restart to restart the Nimbus service, GET /api/v1/nimbus/status to check health, and POST /api/v1/nimbus/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Nimbus service:
- ERR-1131: connection pool exhausted
- ERR-1132: upstream timeout exceeded
- ERR-1133: invalid authentication token
- ERR-1134: payload schema validation failed
When you see ERR-1131, the connection pool is exhausted; increase NIMBUS_NIMBUS_POOL_SIZE. ERR-1132 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Nimbus service. If you observe connection drops or high latency, first check GET /api/v1/nimbus/status, then review recent error codes. Restart with `nimbusctl nimbus restart` or POST /api/v1/nimbus/restart. Persistent timeouts usually mean NIMBUS_NIMBUS_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to Data Team.
