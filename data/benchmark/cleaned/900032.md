# Fjord Service

## Overview

The Fjord service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Fjord exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Fjord v2.1.0. Owner: SRE. This document describes configuration, endpoints, error codes, and troubleshooting for Fjord.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_FJORD_TIMEOUT_MS (default 3775)
- NIMBUS_FJORD_MAX_RETRIES (default 6)
- NIMBUS_FJORD_POOL_SIZE (default 44)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_FJORD_TIMEOUT_MS affects request timeout behavior for Fjord.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/fjord/restart
- GET /api/v1/fjord/status
- POST /api/v1/fjord/cache/flush
Use POST /api/v1/fjord/restart to restart the Fjord service, GET /api/v1/fjord/status to check health, and POST /api/v1/fjord/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Fjord service:
- ERR-1311: connection pool exhausted
- ERR-1312: upstream timeout exceeded
- ERR-1313: invalid authentication token
- ERR-1314: payload schema validation failed
When you see ERR-1311, the connection pool is exhausted; increase NIMBUS_FJORD_POOL_SIZE. ERR-1312 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Fjord service. If you observe connection drops or high latency, first check GET /api/v1/fjord/status, then review recent error codes. Restart with `nimbusctl fjord restart` or POST /api/v1/fjord/restart. Persistent timeouts usually mean NIMBUS_FJORD_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to SRE.
