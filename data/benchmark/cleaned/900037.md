# Kraken Service

## Overview

The Kraken service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Kraken exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Kraken v1.6.0. Owner: SRE. This document describes configuration, endpoints, error codes, and troubleshooting for Kraken.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_KRAKEN_TIMEOUT_MS (default 3900)
- NIMBUS_KRAKEN_MAX_RETRIES (default 3)
- NIMBUS_KRAKEN_POOL_SIZE (default 32)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_KRAKEN_TIMEOUT_MS affects request timeout behavior for Kraken.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/kraken/restart
- GET /api/v1/kraken/status
- POST /api/v1/kraken/cache/flush
Use POST /api/v1/kraken/restart to restart the Kraken service, GET /api/v1/kraken/status to check health, and POST /api/v1/kraken/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Kraken service:
- ERR-1361: connection pool exhausted
- ERR-1362: upstream timeout exceeded
- ERR-1363: invalid authentication token
- ERR-1364: payload schema validation failed
When you see ERR-1361, the connection pool is exhausted; increase NIMBUS_KRAKEN_POOL_SIZE. ERR-1362 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Kraken service. If you observe connection drops or high latency, first check GET /api/v1/kraken/status, then review recent error codes. Restart with `nimbusctl kraken restart` or POST /api/v1/kraken/restart. Persistent timeouts usually mean NIMBUS_KRAKEN_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to SRE.
