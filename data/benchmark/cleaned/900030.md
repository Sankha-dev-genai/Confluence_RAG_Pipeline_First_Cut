# Delta Service

## Overview

The Delta service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Delta exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Delta v3.9.0. Owner: Infra Guild. This document describes configuration, endpoints, error codes, and troubleshooting for Delta.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_DELTA_TIMEOUT_MS (default 3725)
- NIMBUS_DELTA_MAX_RETRIES (default 4)
- NIMBUS_DELTA_POOL_SIZE (default 36)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_DELTA_TIMEOUT_MS affects request timeout behavior for Delta.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/delta/restart
- GET /api/v1/delta/status
- POST /api/v1/delta/cache/flush
Use POST /api/v1/delta/restart to restart the Delta service, GET /api/v1/delta/status to check health, and POST /api/v1/delta/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Delta service:
- ERR-1291: connection pool exhausted
- ERR-1292: upstream timeout exceeded
- ERR-1293: invalid authentication token
- ERR-1294: payload schema validation failed
When you see ERR-1291, the connection pool is exhausted; increase NIMBUS_DELTA_POOL_SIZE. ERR-1292 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Delta service. If you observe connection drops or high latency, first check GET /api/v1/delta/status, then review recent error codes. Restart with `nimbusctl delta restart` or POST /api/v1/delta/restart. Persistent timeouts usually mean NIMBUS_DELTA_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to Infra Guild.
