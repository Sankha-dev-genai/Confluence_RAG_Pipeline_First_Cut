# Lumen Service

## Overview

The Lumen service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Lumen exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Lumen v3.1.0. Owner: SRE. This document describes configuration, endpoints, error codes, and troubleshooting for Lumen.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_LUMEN_TIMEOUT_MS (default 3275)
- NIMBUS_LUMEN_MAX_RETRIES (default 6)
- NIMBUS_LUMEN_POOL_SIZE (default 28)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_LUMEN_TIMEOUT_MS affects request timeout behavior for Lumen.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/lumen/restart
- GET /api/v1/lumen/status
- POST /api/v1/lumen/cache/flush
Use POST /api/v1/lumen/restart to restart the Lumen service, GET /api/v1/lumen/status to check health, and POST /api/v1/lumen/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Lumen service:
- ERR-1111: connection pool exhausted
- ERR-1112: upstream timeout exceeded
- ERR-1113: invalid authentication token
- ERR-1114: payload schema validation failed
When you see ERR-1111, the connection pool is exhausted; increase NIMBUS_LUMEN_POOL_SIZE. ERR-1112 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Lumen service. If you observe connection drops or high latency, first check GET /api/v1/lumen/status, then review recent error codes. Restart with `nimbusctl lumen restart` or POST /api/v1/lumen/restart. Persistent timeouts usually mean NIMBUS_LUMEN_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to SRE.
