# Echo Service

## Overview

The Echo service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Echo exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Echo v1.0.0. Owner: Platform Team. This document describes configuration, endpoints, error codes, and troubleshooting for Echo.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_ECHO_TIMEOUT_MS (default 3750)
- NIMBUS_ECHO_MAX_RETRIES (default 5)
- NIMBUS_ECHO_POOL_SIZE (default 40)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_ECHO_TIMEOUT_MS affects request timeout behavior for Echo.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/echo/restart
- GET /api/v1/echo/status
- POST /api/v1/echo/cache/flush
Use POST /api/v1/echo/restart to restart the Echo service, GET /api/v1/echo/status to check health, and POST /api/v1/echo/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Echo service:
- ERR-1301: connection pool exhausted
- ERR-1302: upstream timeout exceeded
- ERR-1303: invalid authentication token
- ERR-1304: payload schema validation failed
When you see ERR-1301, the connection pool is exhausted; increase NIMBUS_ECHO_POOL_SIZE. ERR-1302 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Echo service. If you observe connection drops or high latency, first check GET /api/v1/echo/status, then review recent error codes. Restart with `nimbusctl echo restart` or POST /api/v1/echo/restart. Persistent timeouts usually mean NIMBUS_ECHO_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to Platform Team.
