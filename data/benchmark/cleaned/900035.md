# Ionic Service

## Overview

The Ionic service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Ionic exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Ionic v2.4.0. Owner: Infra Guild. This document describes configuration, endpoints, error codes, and troubleshooting for Ionic.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_IONIC_TIMEOUT_MS (default 3850)
- NIMBUS_IONIC_MAX_RETRIES (default 5)
- NIMBUS_IONIC_POOL_SIZE (default 24)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_IONIC_TIMEOUT_MS affects request timeout behavior for Ionic.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/ionic/restart
- GET /api/v1/ionic/status
- POST /api/v1/ionic/cache/flush
Use POST /api/v1/ionic/restart to restart the Ionic service, GET /api/v1/ionic/status to check health, and POST /api/v1/ionic/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Ionic service:
- ERR-1341: connection pool exhausted
- ERR-1342: upstream timeout exceeded
- ERR-1343: invalid authentication token
- ERR-1344: payload schema validation failed
When you see ERR-1341, the connection pool is exhausted; increase NIMBUS_IONIC_POOL_SIZE. ERR-1342 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Ionic service. If you observe connection drops or high latency, first check GET /api/v1/ionic/status, then review recent error codes. Restart with `nimbusctl ionic restart` or POST /api/v1/ionic/restart. Persistent timeouts usually mean NIMBUS_IONIC_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to Infra Guild.
