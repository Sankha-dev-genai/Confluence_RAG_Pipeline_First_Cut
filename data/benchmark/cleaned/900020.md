# Talc Service

## Overview

The Talc service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Talc exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Talc v2.9.0. Owner: Infra Guild. This document describes configuration, endpoints, error codes, and troubleshooting for Talc.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_TALC_TIMEOUT_MS (default 3475)
- NIMBUS_TALC_MAX_RETRIES (default 6)
- NIMBUS_TALC_POOL_SIZE (default 28)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_TALC_TIMEOUT_MS affects request timeout behavior for Talc.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/talc/restart
- GET /api/v1/talc/status
- POST /api/v1/talc/cache/flush
Use POST /api/v1/talc/restart to restart the Talc service, GET /api/v1/talc/status to check health, and POST /api/v1/talc/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Talc service:
- ERR-1191: connection pool exhausted
- ERR-1192: upstream timeout exceeded
- ERR-1193: invalid authentication token
- ERR-1194: payload schema validation failed
When you see ERR-1191, the connection pool is exhausted; increase NIMBUS_TALC_POOL_SIZE. ERR-1192 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Talc service. If you observe connection drops or high latency, first check GET /api/v1/talc/status, then review recent error codes. Restart with `nimbusctl talc restart` or POST /api/v1/talc/restart. Persistent timeouts usually mean NIMBUS_TALC_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to Infra Guild.
