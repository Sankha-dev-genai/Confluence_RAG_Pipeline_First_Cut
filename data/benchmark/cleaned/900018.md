# Rime Service

## Overview

The Rime service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Rime exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Rime v3.7.0. Owner: API Team. This document describes configuration, endpoints, error codes, and troubleshooting for Rime.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_RIME_TIMEOUT_MS (default 3425)
- NIMBUS_RIME_MAX_RETRIES (default 4)
- NIMBUS_RIME_POOL_SIZE (default 20)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_RIME_TIMEOUT_MS affects request timeout behavior for Rime.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/rime/restart
- GET /api/v1/rime/status
- POST /api/v1/rime/cache/flush
Use POST /api/v1/rime/restart to restart the Rime service, GET /api/v1/rime/status to check health, and POST /api/v1/rime/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Rime service:
- ERR-1171: connection pool exhausted
- ERR-1172: upstream timeout exceeded
- ERR-1173: invalid authentication token
- ERR-1174: payload schema validation failed
When you see ERR-1171, the connection pool is exhausted; increase NIMBUS_RIME_POOL_SIZE. ERR-1172 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Rime service. If you observe connection drops or high latency, first check GET /api/v1/rime/status, then review recent error codes. Restart with `nimbusctl rime restart` or POST /api/v1/rime/restart. Persistent timeouts usually mean NIMBUS_RIME_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to API Team.
