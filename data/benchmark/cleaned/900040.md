# Nova Service

## Overview

The Nova service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Nova exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Nova v1.9.0. Owner: Infra Guild. This document describes configuration, endpoints, error codes, and troubleshooting for Nova.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_NOVA_TIMEOUT_MS (default 3975)
- NIMBUS_NOVA_MAX_RETRIES (default 6)
- NIMBUS_NOVA_POOL_SIZE (default 44)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_NOVA_TIMEOUT_MS affects request timeout behavior for Nova.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/nova/restart
- GET /api/v1/nova/status
- POST /api/v1/nova/cache/flush
Use POST /api/v1/nova/restart to restart the Nova service, GET /api/v1/nova/status to check health, and POST /api/v1/nova/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Nova service:
- ERR-1391: connection pool exhausted
- ERR-1392: upstream timeout exceeded
- ERR-1393: invalid authentication token
- ERR-1394: payload schema validation failed
When you see ERR-1391, the connection pool is exhausted; increase NIMBUS_NOVA_POOL_SIZE. ERR-1392 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Nova service. If you observe connection drops or high latency, first check GET /api/v1/nova/status, then review recent error codes. Restart with `nimbusctl nova restart` or POST /api/v1/nova/restart. Persistent timeouts usually mean NIMBUS_NOVA_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to Infra Guild.
