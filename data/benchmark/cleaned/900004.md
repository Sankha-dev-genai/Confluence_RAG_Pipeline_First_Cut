# Dune Service

## Overview

The Dune service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Dune exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Dune v1.3.0. Owner: Data Team. This document describes configuration, endpoints, error codes, and troubleshooting for Dune.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_DUNE_TIMEOUT_MS (default 3075)
- NIMBUS_DUNE_MAX_RETRIES (default 6)
- NIMBUS_DUNE_POOL_SIZE (default 28)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_DUNE_TIMEOUT_MS affects request timeout behavior for Dune.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/dune/restart
- GET /api/v1/dune/status
- POST /api/v1/dune/cache/flush
Use POST /api/v1/dune/restart to restart the Dune service, GET /api/v1/dune/status to check health, and POST /api/v1/dune/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Dune service:
- ERR-1031: connection pool exhausted
- ERR-1032: upstream timeout exceeded
- ERR-1033: invalid authentication token
- ERR-1034: payload schema validation failed
When you see ERR-1031, the connection pool is exhausted; increase NIMBUS_DUNE_POOL_SIZE. ERR-1032 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Dune service. If you observe connection drops or high latency, first check GET /api/v1/dune/status, then review recent error codes. Restart with `nimbusctl dune restart` or POST /api/v1/dune/restart. Persistent timeouts usually mean NIMBUS_DUNE_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to Data Team.
