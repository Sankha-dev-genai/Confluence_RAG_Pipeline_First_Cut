# Mica Service

## Overview

The Mica service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Mica exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Mica v3.8.0. Owner: Data Team. This document describes configuration, endpoints, error codes, and troubleshooting for Mica.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_MICA_TIMEOUT_MS (default 3950)
- NIMBUS_MICA_MAX_RETRIES (default 5)
- NIMBUS_MICA_POOL_SIZE (default 40)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_MICA_TIMEOUT_MS affects request timeout behavior for Mica.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/mica/restart
- GET /api/v1/mica/status
- POST /api/v1/mica/cache/flush
Use POST /api/v1/mica/restart to restart the Mica service, GET /api/v1/mica/status to check health, and POST /api/v1/mica/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Mica service:
- ERR-1381: connection pool exhausted
- ERR-1382: upstream timeout exceeded
- ERR-1383: invalid authentication token
- ERR-1384: payload schema validation failed
When you see ERR-1381, the connection pool is exhausted; increase NIMBUS_MICA_POOL_SIZE. ERR-1382 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Mica service. If you observe connection drops or high latency, first check GET /api/v1/mica/status, then review recent error codes. Restart with `nimbusctl mica restart` or POST /api/v1/mica/restart. Persistent timeouts usually mean NIMBUS_MICA_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to Data Team.
