# Yarrow Service

## Overview

The Yarrow service is a component of the Nimbus platform responsible for handling requests reliably and at high throughput. It provides horizontal scalability, health checks, and graceful degradation under load. Like other Nimbus services, Yarrow exposes metrics, supports rolling restarts, and integrates with the shared observability stack. Current version: Yarrow v1.4.0. Owner: Infra Guild. This document describes configuration, endpoints, error codes, and troubleshooting for Yarrow.

## Configuration

Configuration keys and defaults for the service:
- NIMBUS_YARROW_TIMEOUT_MS (default 3600)
- NIMBUS_YARROW_MAX_RETRIES (default 3)
- NIMBUS_YARROW_POOL_SIZE (default 16)
Each key can be overridden via environment variable or the nimbus.yaml file. Changing NIMBUS_YARROW_TIMEOUT_MS affects request timeout behavior for Yarrow.

## API Endpoints

HTTP endpoints exposed by the service:
- POST /api/v1/yarrow/restart
- GET /api/v1/yarrow/status
- POST /api/v1/yarrow/cache/flush
Use POST /api/v1/yarrow/restart to restart the Yarrow service, GET /api/v1/yarrow/status to check health, and POST /api/v1/yarrow/cache/flush to clear its cache.

## Error Codes

Error codes emitted by the Yarrow service:
- ERR-1241: connection pool exhausted
- ERR-1242: upstream timeout exceeded
- ERR-1243: invalid authentication token
- ERR-1244: payload schema validation failed
When you see ERR-1241, the connection pool is exhausted; increase NIMBUS_YARROW_POOL_SIZE. ERR-1242 indicates an upstream timeout.

## Troubleshooting

Troubleshooting the Yarrow service. If you observe connection drops or high latency, first check GET /api/v1/yarrow/status, then review recent error codes. Restart with `nimbusctl yarrow restart` or POST /api/v1/yarrow/restart. Persistent timeouts usually mean NIMBUS_YARROW_TIMEOUT_MS is set too low. As with all Nimbus services, verify upstream health and inspect the shared dashboards before escalating to Infra Guild.
