An **operating system** (**OS**) is [system software](/wiki/System_software "System software") that manages [computer hardware](/wiki/Computer_hardware "Computer hardware") and [software](/wiki/Software "Software") resources, and provides common [services](/wiki/Daemon_(computing) "Daemon (computing)") for [computer programs](/wiki/Computer_program "Computer program").[[1]](#cite_note-1)

[Time-sharing](/wiki/Time-sharing "Time-sharing") operating systems [schedule tasks](/wiki/Scheduler_(computing) "Scheduler (computing)") for efficient use of the system and may also include accounting software for cost allocation of [processor time](/wiki/Scheduling_(computing) "Scheduling (computing)"), [mass storage](/wiki/Mass_storage "Mass storage"), peripherals, and other resources.

For hardware functions such as [input and output](/wiki/Input_and_output "Input and output") and [memory allocation](/wiki/Memory_allocation "Memory allocation"), the operating system acts as an intermediary between programs and the computer hardware,[[2]](#cite_note-2)[[3]](#cite_note-3) although the application code is usually executed directly by the hardware and frequently makes [system calls](/wiki/System_call "System call") to an OS function or is [interrupted](/wiki/Interrupt "Interrupt") by it. Operating systems are found on many devices that contain a computer – from cellular phones and video game consoles to [web servers](/wiki/Web_server "Web server") and [supercomputers](/wiki/Supercomputer "Supercomputer").

As of November 2025[[update]](https://en.wikipedia.org/w/index.php?title=Operating_system&action=edit), [Android](/wiki/Android_(operating_system) "Android (operating system)") is the most popular operating system, with a 38% market share, followed by [Microsoft Windows](/wiki/Microsoft_Windows "Microsoft Windows") at 33%, [iOS](/wiki/IOS "IOS") and [iPadOS](/wiki/IPadOS "IPadOS") at 15%, [macOS](/wiki/MacOS "MacOS") at 4%, and [Linux](/wiki/Linux "Linux") at 1%. Android, iOS, and iPadOS are operating systems for mobile devices such as smartphones, while Windows, macOS, and Linux are for desktop computers.[[4]](#cite_note-gs.statcounter.com-4) [Linux distributions](/wiki/Linux_distribution "Linux distribution") are dominant in the server and supercomputing sectors and number in the thousands.[[5]](#cite_note-5)[[6]](#cite_note-6) Other specialized classes of operating systems (special-purpose operating systems),[[7]](#cite_note-auto-7)[[8]](#cite_note-8) such as [embedded](/wiki/Embedded_system "Embedded system") and real-time systems, exist for many applications. [Security-focused operating systems](/wiki/Security-focused_operating_system "Security-focused operating system") also exist. Some operating systems have low system requirements (e.g. [light-weight Linux distribution](/wiki/Light-weight_Linux_distribution "Light-weight Linux distribution")). Others may have higher system requirements.

Some operating systems require installation or may come pre-installed with purchased computers ([OEM](/wiki/OEM "OEM")-installation), whereas others may run directly from media (i.e. [live CD](/wiki/Live_CD "Live CD")) or flash memory (i.e. a LiveUSB from a [USB](/wiki/USB_flash_drive "USB flash drive") stick).

## Definition and purpose

An operating system is difficult to define,[[9]](#cite_note-FOOTNOTETanenbaumBos20234-9) but has been called "the [layer of software](/wiki/Abstraction_layer "Abstraction layer") that manages a computer's resources for its users and their [applications](/wiki/Application_software "Application software")".[[10]](#cite_note-FOOTNOTEAndersonDahlin20146-10) Operating systems include the software that is always running, called a [kernel](/wiki/Kernel_(operating_system) "Kernel (operating system)")—but can include other software as well.[[9]](#cite_note-FOOTNOTETanenbaumBos20234-9)[[11]](#cite_note-FOOTNOTESilberschatz_et_al.20186-11) The two other types of programs that can run on a computer are [system programs](/wiki/System_software "System software")—which are associated with the operating system, but may not be part of the kernel—and applications—all other software.[[11]](#cite_note-FOOTNOTESilberschatz_et_al.20186-11)

There are three main purposes that an operating system fulfills:[[12]](#cite_note-FOOTNOTEAndersonDahlin20147-12)

- Operating systems allocate resources between different applications, deciding when they will receive [central processing unit](/wiki/Central_processing_unit "Central processing unit") (CPU) time or space in [memory](/wiki/Computer_memory "Computer memory").[[12]](#cite_note-FOOTNOTEAndersonDahlin20147-12) On modern [personal computers](/wiki/Personal_computer "Personal computer"), users often want to run several applications at once. In order to ensure that one program cannot monopolize the computer's limited hardware resources, the operating system gives each application a share of the resource, either in time (CPU) or space (memory).[[13]](#cite_note-FOOTNOTEAndersonDahlin20149–10-13)[[14]](#cite_note-FOOTNOTETanenbaumBos20236–7-14) The operating system also must isolate applications from each other to protect them from errors and security vulnerabilities in another application's code, but enable communications between different applications.[[15]](#cite_note-FOOTNOTEAndersonDahlin201410-15)
- Operating systems provide an interface that abstracts the details of [hardware](/wiki/Computer_hardware "Computer hardware") access (such as physical memory) to make things easier for programmers.[[12]](#cite_note-FOOTNOTEAndersonDahlin20147-12)[[16]](#cite_note-FOOTNOTETanenbaumBos20235-16) [Virtualization](/wiki/Virtualization "Virtualization") also enables the operating system to mask limited hardware resources; for example, [virtual memory](/wiki/Virtual_memory "Virtual memory") can provide a program with the illusion of nearly unlimited memory that exceeds the computer's actual memory.[[17]](#cite_note-FOOTNOTEAndersonDahlin201411-17)
- Operating systems provide common services, such as an interface for accessing network and disk devices. This enables an application to be run on different hardware without needing to be rewritten.[[18]](#cite_note-FOOTNOTEAndersonDahlin20147,_9,_13-18) Which services to include in an operating system varies greatly, and this functionality makes up the great majority of code for most operating systems.[[19]](#cite_note-FOOTNOTEAndersonDahlin201412–13-19)

## Types of operating systems

### Multicomputer operating systems

With [multiprocessors](/wiki/Multiprocessor "Multiprocessor") multiple CPUs share memory. A [multicomputer](/wiki/Multicomputer "Multicomputer") or [cluster computer](/wiki/Cluster_computer "Cluster computer") has multiple CPUs, each of which [has its own memory](/wiki/Distributed_memory "Distributed memory"). Multicomputers were developed because large multiprocessors are difficult to engineer and prohibitively expensive;[[20]](#cite_note-FOOTNOTETanenbaumBos2023557-20) they are universal in [cloud computing](/wiki/Cloud_computing "Cloud computing") because of the size of the machine needed.[[21]](#cite_note-FOOTNOTETanenbaumBos2023558-21) The different CPUs often need to send and receive messages to each other;[[22]](#cite_note-FOOTNOTETanenbaumBos2023565-22) to ensure good performance, the operating systems for these machines need to minimize this copying of [packets](/wiki/Network_packet "Network packet").[[23]](#cite_note-FOOTNOTETanenbaumBos2023562-23) Newer systems are often [multiqueue](/w/index.php?title=Multiqueue&action=edit&redlink=1 "Multiqueue (page does not exist)")—separating groups of users into separate [queues](/wiki/Priority_queue "Priority queue")—to reduce the need for packet copying and support more concurrent users.[[24]](#cite_note-FOOTNOTETanenbaumBos2023563-24) Another technique is [remote direct memory access](/wiki/Remote_direct_memory_access "Remote direct memory access"), which enables each CPU to access memory belonging to other CPUs.[[22]](#cite_note-FOOTNOTETanenbaumBos2023565-22) Multicomputer operating systems often support [remote procedure calls](/wiki/Remote_procedure_call "Remote procedure call") where a CPU can call a [procedure](/wiki/Procedural_programming "Procedural programming") on another CPU,[[25]](#cite_note-FOOTNOTETanenbaumBos2023569-25) or [distributed shared memory](/wiki/Distributed_shared_memory "Distributed shared memory"), in which the operating system uses [virtualization](/wiki/Virtualization "Virtualization") to generate shared memory that does not physically exist.[[26]](#cite_note-FOOTNOTETanenbaumBos2023571-26)

### Distributed systems

A [distributed system](/wiki/Distributed_system "Distributed system") is a group of distinct, [networked](/wiki/Computer_network "Computer network") computers—each of which might have their own operating system and file system. Unlike multicomputers, they may be dispersed anywhere in the world.[[27]](#cite_note-FOOTNOTETanenbaumBos2023579-27) [Middleware](/wiki/Middleware "Middleware"), an additional software layer between the operating system and applications, is often used to improve consistency. Although it functions similarly to an operating system, it is not a true operating system.[[28]](#cite_note-FOOTNOTETanenbaumBos2023581-28)

### Embedded

[Embedded operating systems](/wiki/Embedded_operating_system "Embedded operating system") are designed to be used in [embedded computer systems](/wiki/Embedded_system "Embedded system"), whether they are [internet of things](/wiki/Internet_of_things "Internet of things") objects or not connected to a network. Embedded systems include many household appliances. The distinguishing factor is that they do not load user-installed software. Consequently, they do not need protection between different applications, enabling simpler designs. Very small operating systems might run in less than 10 [kilobytes](/wiki/Kilobytes "Kilobytes"),[[29]](#cite_note-FOOTNOTETanenbaumBos202337–38-29) and the smallest are for [smart cards](/wiki/Smart_cards "Smart cards").[[30]](#cite_note-FOOTNOTETanenbaumBos202339-30) Examples include [Embedded Linux](/wiki/Embedded_Linux "Embedded Linux"), [QNX](/wiki/QNX "QNX"), [VxWorks](/wiki/VxWorks "VxWorks"), and the extra-small systems [RIOT](/wiki/RIOT_(operating_system) "RIOT (operating system)") and [TinyOS](/wiki/TinyOS "TinyOS").[[31]](#cite_note-FOOTNOTETanenbaumBos202338-31)

### Real-time

A [real-time operating system](/wiki/Real-time_operating_system "Real-time operating system") is an operating system that guarantees to process [events](/wiki/Event_(computing) "Event (computing)") or data by or at a specific moment in time. Hard real-time systems require exact timing and are common in [manufacturing](/wiki/Manufacturing "Manufacturing"), [avionics](/wiki/Avionics "Avionics"), military, and other similar uses.[[31]](#cite_note-FOOTNOTETanenbaumBos202338-31) With soft real-time systems, the occasional missed event is acceptable; this category often includes audio or multimedia systems, as well as smartphones.[[31]](#cite_note-FOOTNOTETanenbaumBos202338-31) In order for hard real-time systems be sufficiently exact in their timing, often they are just a library with no protection between applications, such as [eCos](/wiki/ECos "ECos").[[31]](#cite_note-FOOTNOTETanenbaumBos202338-31)

### Hypervisor

A [hypervisor](/wiki/Hypervisor "Hypervisor") is an operating system that runs a [virtual machine](/wiki/Virtual_machine "Virtual machine"). The virtual machine is an application that emulates hardware; in other words, it operates as much as possible like the actual hardware the operating system was designed to run on.[[17]](#cite_note-FOOTNOTEAndersonDahlin201411-17)[[32]](#cite_note-FOOTNOTESilberschatz_et_al.2018701-32) Virtual machines can be paused, saved, and resumed, making them useful for operating systems research, development,[[33]](#cite_note-FOOTNOTESilberschatz_et_al.2018705-33) and debugging.[[34]](#cite_note-FOOTNOTEAndersonDahlin201412-34) They also enhance portability by enabling applications to be run on a computer even if they are not compatible with the base operating system.[[17]](#cite_note-FOOTNOTEAndersonDahlin201411-17)

### Library

A *library operating system* (libOS) is one in which the services that a typical operating system provides, such as networking, are provided in the form of [libraries](/wiki/Library_(computing) "Library (computing)") and composed with a single application and configuration code to construct a [unikernel](/wiki/Unikernel "Unikernel"):
[[35]](#cite_note-Unikernels-35) a specialized (only the absolute necessary pieces of code are extracted from libraries and bound together
[[36]](#cite_note-Unikraft-Build-Process-36)), [single address space](/wiki/Single_address_space_operating_system "Single address space operating system"), machine image that can be deployed to cloud or embedded environments.

The operating system code and application code are not executed in separated [protection domains](/wiki/Protection_ring "Protection ring") (there is only a single application running, at least conceptually, so there is no need to prevent interference between applications) and OS services are accessed via simple library calls (potentially [inlining](/wiki/Inline_expansion "Inline expansion") them based on compiler thresholds), without the usual overhead of [context switches](/wiki/Context_switch "Context switch"),
[[37]](#cite_note-rise-of-libOS-37) in a way similarly to embedded and real-time OSes. This overhead is not negligible: to the direct cost of mode switching it's necessary to add the indirect pollution of important processor structures (like [CPU caches](/wiki/CPU_cache "CPU cache"), the [instruction pipeline](/wiki/Instruction_pipelining "Instruction pipelining"), and so on) which affects both user-mode and kernel-mode performance.
[[38]](#cite_note-FlexSC-38)

## History

Main article: [History of operating systems](/wiki/History_of_operating_systems "History of operating systems")

[![Image](//upload.wikimedia.org/wikipedia/commons/thumb/3/39/IBM_system_360-50_console_-_MfK_Bern.jpg/250px-IBM_system_360-50_console_-_MfK_Bern.jpg?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](/wiki/File:IBM_system_360-50_console_-_MfK_Bern.jpg)

IBM System/360 Model 50 operator's console and CPU; the operator's console is a [terminal](/wiki/Computer_terminal "Computer terminal") used by the operating system to communicate with the operator.

The first computers in the late 1940s and 1950s were directly programmed either with [plugboards](/wiki/Plugboard "Plugboard") or with [machine code](/wiki/Machine_code "Machine code") inputted on media such as [punch cards](/wiki/Punch_card "Punch card"), without [programming languages](/wiki/Programming_language "Programming language") or operating systems.[[39]](#cite_note-FOOTNOTETanenbaumBos20238-39) After the introduction of the [transistor](/wiki/Transistor "Transistor") in the mid-1950s, [mainframes](/wiki/Mainframe "Mainframe") began to be built. These still needed professional operators[[39]](#cite_note-FOOTNOTETanenbaumBos20238-39) who manually do what a modern operating system would do, such as scheduling programs to run,[[40]](#cite_note-OSTEP_book-40) but mainframes still had rudimentary operating systems such as [Fortran Monitor System](/wiki/Fortran_Monitor_System "Fortran Monitor System") (FMS) and [IBSYS](/wiki/IBSYS "IBSYS").[[41]](#cite_note-FOOTNOTETanenbaumBos202310-41) In the 1960s, [IBM](/wiki/IBM "IBM") introduced the first series of intercompatible computers ([System/360](/wiki/System/360 "System/360")). All of them ran the same operating system—[OS/360](/wiki/OS/360 "OS/360")—which consisted of millions of lines of [assembly language](/wiki/Assembly_language "Assembly language") that had thousands of [bugs](/wiki/Software_bug "Software bug"). The OS/360 also was the first popular operating system to support [multiprogramming](/wiki/Multiprogramming "Multiprogramming"), such that, if one job is blocked waiting for an [input/output](/wiki/Input/output "Input/output") (I/O) operation to complete, another job can use the CPU. Holding multiple jobs in [memory](/wiki/Memory_(computing) "Memory (computing)") required memory partitioning and safeguards against one job accessing the memory allocated to a different job.[[42]](#cite_note-FOOTNOTETanenbaumBos202311–12-42)

Around the same time, [teleprinters](/wiki/Teleprinter "Teleprinter") began to be used as [terminals](/wiki/Computer_terminal "Computer terminal") so multiple users could access the computer simultaneously. The operating system [MULTICS](/wiki/MULTICS "MULTICS") was intended to allow hundreds of users to access a large computer. Despite its limited adoption, it can be considered the precursor to [cloud computing](/wiki/Cloud_computing "Cloud computing"). The [UNIX](/wiki/UNIX "UNIX") operating system originated as a development of MULTICS for a single user.[[43]](#cite_note-FOOTNOTETanenbaumBos202313–14-43) Because UNIX's [source code](/wiki/Source_code "Source code") was available, it became the basis of other, incompatible operating systems, of which the most successful were [AT&T](/wiki/AT%26T "AT&T")'s [System V](/wiki/System_V "System V") and the [University of California](/wiki/University_of_California,_Berkeley "University of California, Berkeley")'s [Berkeley Software Distribution](/wiki/Berkeley_Software_Distribution "Berkeley Software Distribution") (BSD).[[44]](#cite_note-FOOTNOTETanenbaumBos202314–15-44) To increase compatibility, the [IEEE](/wiki/IEEE "IEEE") released the [POSIX](/wiki/POSIX "POSIX") standard for operating system [application programming interfaces](/wiki/Application_programming_interface "Application programming interface") (APIs), which is supported by most UNIX systems. [MINIX](/wiki/MINIX "MINIX") was a stripped-down version of UNIX, developed in 1987 for educational uses, that inspired the commercially available, [free software](/wiki/Free_software "Free software") [Linux](/wiki/Linux "Linux"). Since 2008, MINIX is used in controllers of most [Intel](/wiki/Intel "Intel") [microchips](/wiki/Microchips "Microchips"), while Linux is widespread in [data centers](/wiki/Data_center "Data center") and [Android](/wiki/Android_(operating_system) "Android (operating system)") smartphones.[[45]](#cite_note-FOOTNOTETanenbaumBos202315-45)

### Microcomputers

[![Image](//upload.wikimedia.org/wikipedia/commons/thumb/0/07/MS-Dos_screenshot.png/250px-MS-Dos_screenshot.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](/wiki/File:MS-Dos_screenshot.png)

[Graphical user interface](/wiki/Graphical_user_interface "Graphical user interface") of a [Macintosh](/wiki/Macintosh "Macintosh")

The invention of [large scale integration](/wiki/Large_scale_integration "Large scale integration") enabled the production of [personal computers](/wiki/Personal_computer "Personal computer") (initially called [microcomputers](/wiki/Microcomputer "Microcomputer")) from around 1980.[[46]](#cite_note-FOOTNOTETanenbaumBos202315–16-46) For around five years, the [CP/M](/wiki/CP/M "CP/M") (Control Program for Microcomputers) was the most popular operating system for microcomputers.[[47]](#cite_note-FOOTNOTETanenbaumBos202316-47) Later, IBM bought a [disk operating system](/wiki/Disk_operating_system "Disk operating system") from [Microsoft](/wiki/Microsoft "Microsoft"), which IBM sold as [IBM PC DOS](/wiki/IBM_PC_DOS "IBM PC DOS") and Microsoft branded as [MS-DOS](/wiki/MS-DOS "MS-DOS") (MicroSoft Disk Operating System) and was widely used on [IBM PC compatible](/wiki/IBM_PC_compatible "IBM PC compatible") microcomputers. Later versions increased their sophistication, in part by borrowing features from UNIX.[[47]](#cite_note-FOOTNOTETanenbaumBos202316-47)

The first popular computer to use a [graphical user interface](/wiki/Graphical_user_interface "Graphical user interface") (GUI) was [Apple](/wiki/Apple_Inc. "Apple Inc.")'s [Macintosh](/wiki/Macintosh "Macintosh"). The GUI proved much more [user friendly](/wiki/User_friendly "User friendly") than the text-only [command-line interface](/wiki/Command-line_interface "Command-line interface") of earlier operating systems. This success prompted Microsoft to add a GUI overlay to MS-DOS called [Windows](/wiki/Windows "Windows"). Windows later was rewritten as a stand-alone operating system, [Windows NT](/wiki/Windows_NT "Windows NT"), borrowing so many features from another OS ([VAX/VMS](/wiki/VAX/VMS "VAX/VMS")) that a large [legal settlement](/wiki/Legal_settlement "Legal settlement") was paid.[[48]](#cite_note-FOOTNOTETanenbaumBos202317-48) In the 21st century, Windows continues to be popular on personal computers but has less [market share](/wiki/Market_share "Market share") of servers. UNIX operating systems, especially Linux, are the most popular on [enterprise systems](/wiki/Enterprise_system "Enterprise system") and servers but are also used on [mobile devices](/wiki/Mobile_device "Mobile device") and many other computer systems.[[49]](#cite_note-FOOTNOTETanenbaumBos202318-49)

On mobile devices, [Symbian OS](/wiki/Symbian_OS "Symbian OS") was dominant at first, being usurped by [BlackBerry OS](/wiki/BlackBerry_OS "BlackBerry OS") (introduced 2002) and [iOS](/wiki/IOS "IOS") for [iPhones](/wiki/IPhone "IPhone") (from 2007). Later on, the open-source [Android](/wiki/Android_(operating_system) "Android (operating system)") operating system (introduced 2008), with a Linux kernel and a C library ([Bionic](/wiki/Bionic_(software) "Bionic (software)")) partially based on BSD code, became most popular.[[50]](#cite_note-FOOTNOTETanenbaumBos202319–20-50)

## Components

The components of an operating system are designed to ensure that various parts of a computer function cohesively. With the de facto obsoletion of [DOS](/wiki/Disk_Operating_System "Disk Operating System"), all user [software](/wiki/Software "Software") must interact with the operating system to access hardware.

### Kernel

Main article: [Kernel (operating system)](/wiki/Kernel_(operating_system) "Kernel (operating system)")

The kernel is the part of the operating system that provides [protection](/wiki/Protection_ring "Protection ring") between different applications and users. This protection is key to improving reliability by keeping errors isolated to one program, as well as security by limiting the power of [malicious software](/wiki/Malicious_software "Malicious software") and protecting private data, and ensuring that one program cannot monopolize the computer's resources.[[51]](#cite_note-FOOTNOTEAndersonDahlin201439–40-51) Most operating systems have two modes of operation:[[52]](#cite_note-FOOTNOTETanenbaumBos20232-52) in [user mode](/wiki/User_mode "User mode"), the hardware checks that the software is only executing legal instructions, whereas the kernel has [unrestricted powers](/wiki/Privilege_(computing) "Privilege (computing)") and is not subject to these checks.[[53]](#cite_note-FOOTNOTEAndersonDahlin201441,_45-53) The kernel also manages [memory](/wiki/Random-access_memory "Random-access memory") for other processes and controls access to [input/output](/wiki/Input/output "Input/output") devices.[[54]](#cite_note-FOOTNOTEAndersonDahlin201452–53-54)

#### Program execution

[![Image](//upload.wikimedia.org/wikipedia/commons/thumb/8/8f/Kernel_Layout.svg/250px-Kernel_Layout.svg.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](/wiki/File:Kernel_Layout.svg)

A kernel connects the application software to the hardware of a computer.

The operating system provides an interface between an application program and the computer hardware, so that an application program can interact with the hardware only by obeying rules and procedures programmed into the operating system. The operating system is also a set of services which simplify development and execution of application programs. Executing an application program typically involves the creation of a [process](/wiki/Process_(computing) "Process (computing)") by the operating system [kernel](/wiki/Kernel_(operating_system) "Kernel (operating system)"), which assigns memory space and other resources, establishes a priority for the process in multi-tasking systems, loads program binary code into memory, and initiates execution of the application program, which then interacts with the user and with hardware devices. However, in some systems an application can request that the operating system execute another application within the same process, either as a subroutine or in a separate thread, e.g., the **LINK** and **ATTACH** facilities of [OS/360 and successors](/wiki/OS/360_and_successors "OS/360 and successors").

#### Interrupts

Main article: [Interrupt](/wiki/Interrupt "Interrupt")

An [interrupt](/wiki/Interrupt "Interrupt") (also known as an [abort](/wiki/Abort_(computing) "Abort (computing)"), [exception](/wiki/Exception_handling "Exception handling"), *fault*, [signal](/wiki/Signal_(IPC) "Signal (IPC)"),[[55]](#cite_note-lpi-ch20-p388_quote1-55) or *trap*)[[56]](#cite_note-Hyde_1996-56) provides an efficient way for most operating systems to react to the environment. Interrupts cause the [central processing unit](/wiki/Central_processing_unit "Central processing unit") (CPU) to have a [control flow](/wiki/Control_flow "Control flow") change away from the currently running program to an [interrupt handler](/wiki/Interrupt_handler "Interrupt handler"), also known as an interrupt service routine (ISR).[[57]](#cite_note-sco-ch5-p308_a-57)[[58]](#cite_note-osc-ch2-p32_a-58) An interrupt service routine may cause the [central processing unit](/wiki/Central_processing_unit "Central processing unit") (CPU) to have a [context switch](/wiki/Context_switch "Context switch").[[59]](#cite_note-osc-ch4-p105-59)[[a]](#cite_note-60) The details of how a computer processes an interrupt vary from architecture to architecture, and the details of how interrupt service routines behave vary from operating system to operating system.[[60]](#cite_note-osc-ch2-p31-61) However, several interrupt functions are common.[[60]](#cite_note-osc-ch2-p31-61) The architecture and operating system must:[[60]](#cite_note-osc-ch2-p31-61)

1. transfer control to an interrupt service routine.
2. save the state of the currently running process.
3. restore the state after the interrupt is serviced.

##### Software interrupt

A software interrupt is a message to a [process](/wiki/Process_(computing) "Process (computing)") that an event has occurred.[[55]](#cite_note-lpi-ch20-p388_quote1-55) This contrasts with a *hardware interrupt*—which is a message to the [central processing unit](/wiki/Central_processing_unit "Central processing unit") (CPU) that an event has occurred.[[61]](#cite_note-osc-ch2-p30-62) Software interrupts are similar to hardware interrupts—there is a change away from the currently running process.[[62]](#cite_note-lpi-ch20-p388_quote2-63) Similarly, both hardware and software interrupts execute an [interrupt service routine](/wiki/Interrupt_handler "Interrupt handler").

Software interrupts may be normally occurring events. It is expected that a [time slice](/wiki/Preemption_(computing)#Time_slice "Preemption (computing)") will occur, so the kernel will have to perform a [context switch](/wiki/Context_switch "Context switch").[[63]](#cite_note-lpi-ch20-p388_quote3-64) A [computer program](/wiki/Computer_program "Computer program") may set a timer to go off after a few seconds in case too much data causes an algorithm to take too long.[[64]](#cite_note-lpi-ch20-p388-65)

Software interrupts may be error conditions, such as a malformed [machine instruction](/wiki/Machine_code "Machine code").[[64]](#cite_note-lpi-ch20-p388-65) However, the most common error conditions are [division by zero](/wiki/Division_by_zero "Division by zero") and [accessing an invalid memory address](/wiki/Segmentation_fault "Segmentation fault").[[64]](#cite_note-lpi-ch20-p388-65)

[Users](/wiki/User_(computing) "User (computing)") can send messages to the kernel to modify the behavior of a currently running process.[[64]](#cite_note-lpi-ch20-p388-65) For example, in the [command-line environment](/wiki/Command-line_interface "Command-line interface"), pressing the *interrupt character* (usually [Control-C](/wiki/Control-C "Control-C")) might terminate the currently running process.[[64]](#cite_note-lpi-ch20-p388-65)

To generate *software interrupts* for [x86](/wiki/X86 "X86") CPUs, the [INT](/wiki/INT_(x86_instruction) "INT (x86 instruction)") [assembly language](/wiki/Assembly_language "Assembly language") instruction is available.[[65]](#cite_note-intel-developer-66) The syntax is `INT X`, where `X` is the offset number (in [hexadecimal](/wiki/Hexadecimal "Hexadecimal") format) to the [interrupt vector table](/wiki/Interrupt_vector_table "Interrupt vector table").

##### Signal

To generate *software interrupts* in [Unix-like](/wiki/Unix-like "Unix-like") operating systems, the `kill(pid,signum)` [system call](/wiki/System_call "System call") will send a [signal](/wiki/Signal_(IPC) "Signal (IPC)") to another process.[[66]](#cite_note-duos-p200-67) `pid` is the [process identifier](/wiki/Process_identifier "Process identifier") of the receiving process. `signum` is the signal number (in [mnemonic](/wiki/Mnemonic "Mnemonic") format)[[b]](#cite_note-68) to be sent. (The abrasive name of `kill` was chosen because early implementations only terminated the process.)[[67]](#cite_note-lpi-ch20-p400-69)

In Unix-like operating systems, *signals* inform processes of the occurrence of asynchronous events.[[66]](#cite_note-duos-p200-67) To communicate asynchronously, interrupts are required.[[68]](#cite_note-sco-ch5-p308_b-70) One reason a process needs to asynchronously communicate to another process is to solve a variation of the classic [reader/writer problem](/wiki/Readers%E2%80%93writers_problem "Readers–writers problem").[[69]](#cite_note-osc-p182-71) The writer receives a pipe from the [shell](/wiki/Shell_(computing) "Shell (computing)") for its output to be sent to the reader's input stream.[[70]](#cite_note-usp-ch6-p153-72) The [command-line](/wiki/Command-line_interface "Command-line interface") syntax is `alpha | bravo`. `alpha` will write to the pipe when its computation is ready and then sleep in the wait queue.[[71]](#cite_note-usp-ch6-p148-73) `bravo` will then be moved to the [ready queue](/wiki/Multilevel_feedback_queue "Multilevel feedback queue") and soon will read from its input stream.[[72]](#cite_note-usp-ch6-p149-74) The kernel will generate *software interrupts* to coordinate the piping.[[72]](#cite_note-usp-ch6-p149-74)

*Signals* may be classified into 7 categories.[[66]](#cite_note-duos-p200-67) The categories are:

1. when a process finishes normally.
2. when a process has an error exception.
3. when a process runs out of a system resource.
4. when a process executes an illegal instruction.
5. when a process sets an alarm event.
6. when a process is aborted from the keyboard.
7. when a process has a tracing alert for debugging.

##### Hardware interrupt

[Input/output](/wiki/Input/output "Input/output") (I/O) [devices](/wiki/Peripheral "Peripheral") are slower than the CPU. Therefore, it would slow down the computer if the CPU had to [wait](/wiki/Busy_waiting "Busy waiting") for each I/O to finish. Instead, a computer may implement interrupts for I/O completion, avoiding the need for [polling](/wiki/Polling_(computer_science) "Polling (computer science)") or busy waiting.[[73]](#cite_note-sco-ch5-p292-75)

Some computers require an interrupt for each character or word, costing a significant amount of CPU time. [Direct memory access](/wiki/Direct_memory_access "Direct memory access") (DMA) is an architecture feature to allow devices to bypass the CPU and access [main memory](/wiki/Random-access_memory "Random-access memory") directly.[[74]](#cite_note-A22-6821-7-storage-76) (Separate from the architecture, a device may perform direct memory access[[c]](#cite_note-77) to and from main memory either directly or via a bus.)[[75]](#cite_note-sco-ch5-p294-78)[[d]](#cite_note-79)

|  |  |

When a [computer user](/wiki/User_(computing) "User (computing)") types a key on the keyboard, typically the character appears immediately on the screen. Likewise, when a user moves a [mouse](/wiki/Computer_mouse "Computer mouse"), the [cursor](/wiki/Cursor_(user_interface) "Cursor (user interface)") immediately moves across the screen. Each keystroke and mouse movement generates an *interrupt* called *Interrupt-driven I/O*. An interrupt-driven I/O occurs when a process causes an interrupt for every character[[75]](#cite_note-sco-ch5-p294-78) or word[[76]](#cite_note-80) transmitted.

##### Direct memory access

Devices such as [hard disk drives](/wiki/Hard_disk_drive "Hard disk drive"), [solid-state drives](/wiki/Solid-state_drive "Solid-state drive"), and [magnetic tape](/wiki/Magnetic_tape "Magnetic tape") drives can transfer data at a rate high enough that interrupting the CPU for every byte or word transferred, and having the CPU transfer the byte or word between the device and memory, would require too much CPU time. Data is, instead, transferred between the device and memory independently of the CPU by hardware such as a [channel](/wiki/Channel_I/O "Channel I/O") or a [direct memory access](/wiki/Direct_memory_access "Direct memory access") controller; an interrupt is delivered only when all the data is transferred.[[77]](#cite_note-81)

If a [computer program](/wiki/Computer_program "Computer program") executes a [system call](/wiki/System_call "System call") to perform a block I/O *write* operation, then the system call might execute the following instructions:

- Set the contents of the CPU's [registers](/wiki/Processor_register "Processor register") (including the [program counter](/wiki/Program_counter "Program counter")) into the [process control block](/wiki/Process_control_block "Process control block").[[78]](#cite_note-osc-ch2-p32_b-82)
- Create an entry in the device-status table.[[79]](#cite_note-osc-ch2-p34-83) The operating system maintains this table to keep track of which processes are waiting for which devices. One field in the table is the [memory address](/wiki/Memory_address "Memory address") of the process control block.
- Place all the characters to be sent to the device into a [memory buffer](/wiki/Random-access_memory "Random-access memory").[[68]](#cite_note-sco-ch5-p308_b-70)
- Set the memory address of the memory buffer to a predetermined device register.[[80]](#cite_note-sco-ch5-p295-84)
- Set the buffer size (an integer) to another predetermined register.[[80]](#cite_note-sco-ch5-p295-84)
- Execute the [machine instruction](/wiki/Machine_code "Machine code") to begin the writing.
- Perform a [context switch](/wiki/Context_switch "Context switch") to the next process in the [ready queue](/wiki/Multilevel_feedback_queue "Multilevel feedback queue").

While the writing takes place, the operating system will context switch to other processes as normal. When the device finishes writing, the device will *interrupt* the currently running process by *asserting* an [interrupt request](/wiki/Interrupt_request_(PC_architecture) "Interrupt request (PC architecture)"). The device will also place an integer onto the data bus.[[81]](#cite_note-sco-ch5-p309-85) Upon accepting the interrupt request, the operating system will:

- Push the contents of the [program counter](/wiki/Program_counter "Program counter") (a register) followed by the [status register](/wiki/Status_register "Status register") onto the [call stack](/wiki/Call_stack "Call stack").[[60]](#cite_note-osc-ch2-p31-61)
- Push the contents of the other registers onto the call stack. (Alternatively, the contents of the registers may be placed in a system table.)[[81]](#cite_note-sco-ch5-p309-85)
- Read the integer from the data bus. The integer is an offset to the [interrupt vector table](/wiki/Interrupt_vector_table "Interrupt vector table"). The vector table's instructions will then:

:   - Access the device-status table.
    - Extract the process control block.
    - Perform a context switch back to the writing process.

When the writing process has its [time slice](/wiki/Preemption_(computing)#time_slice "Preemption (computing)") expired, the operating system will:[[82]](#cite_note-sco-ch5-p310-86)

- Pop from the call stack the registers other than the status register and program counter.
- Pop from the call stack the status register.
- Pop from the call stack the address of the next instruction, and set it back into the program counter.

With the program counter now reset, the interrupted process will resume its time slice.[[60]](#cite_note-osc-ch2-p31-61)

#### Memory management

Main article: [Memory management](/wiki/Memory_management "Memory management")

Among other things, a multiprogramming operating system [kernel](/wiki/Kernel_(operating_system) "Kernel (operating system)") must be responsible for managing all system memory which is currently in use by the programs. This ensures that a program does not interfere with memory already in use by another program. Since programs time share, each program must have independent access to memory.

Cooperative memory management, used by many early operating systems, assumes that all programs make voluntary use of the [kernel](/wiki/Kernel_(operating_system) "Kernel (operating system)")'s memory manager, and do not exceed their allocated memory. This system of memory management is almost never seen anymore, since programs often contain bugs which can cause them to exceed their allocated memory. If a program fails, it may cause memory used by one or more other programs to be affected or overwritten. Malicious programs or viruses may purposefully alter another program's memory, or may affect the operation of the operating system itself. With cooperative memory management, it takes only one misbehaved program to [crash](/wiki/Crash_(computing) "Crash (computing)") the system.

[Memory protection](/wiki/Memory_protection "Memory protection") enables the [kernel](/wiki/Kernel_(operating_system) "Kernel (operating system)") to limit a process' access to the computer's memory. Various methods of memory protection exist, including [memory segmentation](/wiki/Memory_segmentation "Memory segmentation") and [paging](/wiki/Paging "Paging"). All methods require some level of hardware support (such as the [80286](/wiki/80286 "80286") MMU), which does not exist in all computers.

In both segmentation and paging, certain [protected mode](/wiki/Protected_mode "Protected mode") registers specify to the CPU what memory address it should allow a running program to access. Attempts to access other addresses trigger an interrupt, which causes the CPU to re-enter [supervisor mode](/wiki/Supervisor_mode "Supervisor mode"), placing the [kernel](/wiki/Kernel_(operating_system) "Kernel (operating system)") in charge. This is called a [segmentation violation](/wiki/Segmentation_violation "Segmentation violation") or Seg-V for short, and since it is both difficult to assign a meaningful result to such an operation, and because it is usually a sign of a misbehaving program, the [kernel](/wiki/Kernel_(operating_system) "Kernel (operating system)") generally resorts to terminating the offending program, and reports the error.

Windows versions 3.1 through ME had some level of memory protection, but programs could easily circumvent the need to use it. A [general protection fault](/wiki/General_protection_fault "General protection fault") would be produced, indicating a segmentation violation had occurred; however, the system would often crash anyway.

#### Virtual memory

Main article: [Virtual memory](/wiki/Virtual_memory "Virtual memory")

Further information: [Page fault](/wiki/Page_fault "Page fault")

[![Image](//upload.wikimedia.org/wikipedia/commons/thumb/6/6e/Virtual_memory.svg/250px-Virtual_memory.svg.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](/wiki/File:Virtual_memory.svg)

Many operating systems can "trick" programs into using memory scattered around the hard disk and RAM as if it is one continuous chunk of memory, called virtual memory.

The use of virtual memory addressing (such as paging or segmentation) means that the kernel can choose what memory each program may use at any given time, allowing the operating system to use the same memory locations for multiple tasks.

If a program tries to access memory that is not accessible[[e]](#cite_note-87) memory, but nonetheless has been allocated to it, the kernel is interrupted (see [§ Memory management](#Memory_management)). This kind of interrupt is typically a [page fault](/wiki/Page_fault "Page fault").

When the kernel detects a page fault it generally adjusts the virtual memory range of the program which triggered it, granting it access to the memory requested. This gives the kernel discretionary power over where a particular application's memory is stored, or even whether or not it has been allocated yet.

In modern operating systems, memory which is accessed less frequently can be temporarily stored on a disk or other media to make that space available for use by other programs. This is called [swapping](/wiki/Paging "Paging"), as an area of memory can be used by multiple programs, and what that memory area contains can be swapped or exchanged on demand.

Virtual memory provides the programmer or the user with the perception that there is a much larger amount of RAM in the computer than is really there.[[83]](#cite_note-Operating_System-88)

### Concurrency

See also: [Computer multitasking](/wiki/Computer_multitasking "Computer multitasking") and [Process management (computing)](/wiki/Process_management_(computing) "Process management (computing)")

[Concurrency](/wiki/Concurrency_(computer_science) "Concurrency (computer science)") refers to the operating system's ability to carry out multiple tasks simultaneously.[[84]](#cite_note-FOOTNOTEAndersonDahlin2014129-89) Virtually all modern operating systems support concurrency.[[85]](#cite_note-FOOTNOTESilberschatz_et_al.2018159-90)

[Threads](/wiki/Thread_(computing) "Thread (computing)") enable splitting a process' work into multiple parts that can run simultaneously.[[86]](#cite_note-FOOTNOTEAndersonDahlin2014130-91) The number of threads is not limited by the number of processors available. If there are more threads than processors, the operating system [kernel](/wiki/Kernel_(operating_system) "Kernel (operating system)") schedules, suspends, and resumes threads, controlling when each thread runs and how much CPU time it receives.[[87]](#cite_note-FOOTNOTEAndersonDahlin2014131-92) During a [context switch](/wiki/Context_switch "Context switch") a running thread is suspended, its state is saved into the [thread control block](/wiki/Thread_control_block "Thread control block") and stack, and the state of the new thread is loaded in.[[88]](#cite_note-FOOTNOTEAndersonDahlin2014157,_159-93) Historically, on many systems a thread could run until it relinquished control ([cooperative multitasking](/wiki/Cooperative_multitasking "Cooperative multitasking")). Because this model can allow a single thread to monopolize the processor, most operating systems now can [interrupt](/wiki/Interrupt "Interrupt") a thread ([preemptive multitasking](/wiki/Preemptive_multitasking "Preemptive multitasking")).[[89]](#cite_note-FOOTNOTEAndersonDahlin2014139-94)

Threads have their own thread ID, [program counter](/wiki/Program_counter "Program counter") (PC), a [register](/wiki/Processor_register "Processor register") set, and a [stack](/wiki/Stack-based_memory_allocation "Stack-based memory allocation"), but share code, [heap](/wiki/Heap_memory "Heap memory") data, and other resources with other threads of the same process.[[90]](#cite_note-FOOTNOTESilberschatz_et_al.2018160-95)[[91]](#cite_note-FOOTNOTEAndersonDahlin2014183-96) Thus, there is less overhead to create a thread than a new process.[[92]](#cite_note-FOOTNOTESilberschatz_et_al.2018162-97) On single-CPU systems, concurrency is switching between processes. Many computers have multiple CPUs.[[93]](#cite_note-FOOTNOTESilberschatz_et_al.2018162–163-98) [Parallelism](/wiki/Parallel_computing "Parallel computing") with multiple threads running on different CPUs can speed up a program, depending on how much of it can be executed concurrently.[[94]](#cite_note-FOOTNOTESilberschatz_et_al.2018164-99)

### File system

Main article: [File system](/wiki/File_system "File system")

See also: [Virtual file system](/wiki/Virtual_file_system "Virtual file system")

[![Image](//upload.wikimedia.org/wikipedia/commons/thumb/5/51/Dolphin_FileManager.png/250px-Dolphin_FileManager.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](/wiki/File:Dolphin_FileManager.png)

[File systems](/wiki/File_system "File system") allow users and programs to organize and sort files on a computer, often through the use of [directories](/wiki/Directory_(computing) "Directory (computing)") (or folders).

Permanent storage devices used in twenty-first century computers, unlike [volatile](/wiki/Volatile_memory "Volatile memory") [dynamic random-access memory](/wiki/Dynamic_random-access_memory "Dynamic random-access memory") (DRAM), are still accessible after a [crash](/wiki/Crash_(computing) "Crash (computing)") or [power failure](/wiki/Power_failure "Power failure"). Permanent ([non-volatile](/wiki/Non-volatile_memory "Non-volatile memory")) storage is much cheaper per byte, but takes several orders of magnitude longer to access, read, and write.[[95]](#cite_note-FOOTNOTEAndersonDahlin2014492,_517-100)[[96]](#cite_note-FOOTNOTETanenbaumBos2023259–260-101) The two main technologies are a [hard drive](/wiki/Hard_drive "Hard drive") consisting of [magnetic disks](/wiki/Magnetic_disk "Magnetic disk"), and [flash memory](/wiki/Flash_memory "Flash memory") (a [solid-state drive](/wiki/Solid-state_drive "Solid-state drive") that stores data in electrical circuits). The latter is more expensive but faster and more durable.[[97]](#cite_note-FOOTNOTEAndersonDahlin2014517,_530-102)[[98]](#cite_note-FOOTNOTETanenbaumBos2023260-103)

[File systems](/wiki/File_system "File system") are an [abstraction](/wiki/Abstraction "Abstraction") used by the operating system to simplify access to permanent storage. They provide human-readable [filenames](/wiki/Filenames "Filenames") and other [metadata](/wiki/Metadata "Metadata"), increase performance via [amortization](/wiki/Amortization_(computer_science) "Amortization (computer science)") of accesses, prevent multiple threads from accessing the same section of memory, and include [checksums](/wiki/Checksums "Checksums") to identify [corruption](/wiki/Data_corruption "Data corruption").[[99]](#cite_note-FOOTNOTEAndersonDahlin2014492–493-104) File systems are composed of files (named collections of data, of an arbitrary size) and [directories](/wiki/Directory_(computing) "Directory (computing)") (also called folders) that list human-readable filenames and other directories.[[100]](#cite_note-FOOTNOTEAndersonDahlin2014496-105) An absolute [file path](/wiki/File_path "File path") begins at the [root directory](/wiki/Root_directory "Root directory") and lists [subdirectories](/wiki/Subdirectories "Subdirectories") divided by punctuation, while a relative path defines the location of a file from a directory.[[101]](#cite_note-FOOTNOTEAndersonDahlin2014496–497-106)[[102]](#cite_note-FOOTNOTETanenbaumBos2023274–275-107)

[System calls](/wiki/System_call "System call") (which are sometimes [wrapped](/wiki/Wrapper_function "Wrapper function") by libraries) enable applications to create, delete, open, and close files, as well as link, read, and write to them. All these operations are carried out by the operating system on behalf of the application.[[103]](#cite_note-FOOTNOTEAndersonDahlin2014502–504-108) The operating system's efforts to reduce latency include storing recently requested blocks of memory in a [cache](/wiki/Cache_(computing) "Cache (computing)") and [prefetching](/wiki/Prefetching "Prefetching") data that the application has not asked for, but might need next.[[104]](#cite_note-FOOTNOTEAndersonDahlin2014507-109) [Device drivers](/wiki/Device_driver "Device driver") are software specific to each [input/output](/wiki/Input/output "Input/output") (I/O) device that enables the operating system to work without modification over different hardware.[[105]](#cite_note-FOOTNOTEAndersonDahlin2014508-110)[[106]](#cite_note-FOOTNOTETanenbaumBos2023359-111)

Another component of file systems is a [dictionary](/wiki/Associative_array "Associative array") that maps a file's name and metadata to the [data block](/wiki/Data_block "Data block") where its contents are stored.[[107]](#cite_note-FOOTNOTEAndersonDahlin2014545-112) Most file systems use directories to convert file names to file numbers. To find the block number, the operating system uses an [index](/wiki/Database_index "Database index") (often implemented as a [tree](/wiki/Tree_(data_structure) "Tree (data structure)")).[[108]](#cite_note-FOOTNOTEAndersonDahlin2014546-113) Separately, there is a free space [map](/wiki/Map_(data_structure) "Map (data structure)") to track free blocks, commonly implemented as a [bitmap](/wiki/Bitmap "Bitmap").[[108]](#cite_note-FOOTNOTEAndersonDahlin2014546-113) Although any free block can be used to store a new file, many operating systems try to group together files in the same directory to maximize performance, or periodically reorganize files to reduce [fragmentation](/wiki/File_system_fragmentation "File system fragmentation").[[109]](#cite_note-FOOTNOTEAndersonDahlin2014547-114)

Maintaining data reliability in the face of a computer crash or hardware failure is another concern.[[110]](#cite_note-FOOTNOTEAndersonDahlin2014589,_591-115) File writing protocols are designed with atomic operations so as not to leave permanent storage in a partially written, inconsistent state in the event of a crash at any point during writing.[[111]](#cite_note-FOOTNOTEAndersonDahlin2014591–592-116) Data corruption is addressed by redundant storage (for example, RAID—[redundant array of inexpensive disks](/wiki/Redundant_array_of_inexpensive_disks "Redundant array of inexpensive disks"))[[112]](#cite_note-FOOTNOTETanenbaumBos2023385–386-117)[[113]](#cite_note-FOOTNOTEAndersonDahlin2014592-118) and [checksums](/wiki/Checksums "Checksums") to detect when data has been corrupted. With multiple layers of checksums and backups of a file, a system can recover from multiple hardware failures. Background processes are often used to detect and recover from data corruption.[[113]](#cite_note-FOOTNOTEAndersonDahlin2014592-118)

### Security

Main article: [Computer security](/wiki/Computer_security "Computer security")

Security means protecting users from other users of the same computer, as well as from those who seeking remote access to it over a network.[[114]](#cite_note-FOOTNOTETanenbaumBos2023605–606-119) Operating systems security rests on achieving the [CIA triad](/wiki/CIA_triad "CIA triad"): confidentiality (unauthorized users cannot access data), integrity (unauthorized users cannot modify data), and availability (ensuring that the system remains available to authorized users, even in the event of a [denial of service attack](/wiki/Denial_of_service_attack "Denial of service attack")).[[115]](#cite_note-FOOTNOTETanenbaumBos2023608-120) As with other computer systems, isolating [security domains](/wiki/Security_domain "Security domain")—in the case of operating systems, the kernel, processes, and [virtual machines](/wiki/Virtual_machine "Virtual machine")—is key to achieving security.[[116]](#cite_note-FOOTNOTETanenbaumBos2023609-121) Other ways to increase security include simplicity to minimize the [attack surface](/wiki/Attack_surface "Attack surface"), locking access to resources by default, checking all requests for authorization, [principle of least authority](/wiki/Principle_of_least_authority "Principle of least authority") (granting the minimum privilege essential for performing a task), [privilege separation](/wiki/Privilege_separation "Privilege separation"), and reducing shared data.[[117]](#cite_note-FOOTNOTETanenbaumBos2023609–610-122)

Some operating system designs are more secure than others. Those with no isolation between the kernel and applications are least secure, while those with a [monolithic kernel](/wiki/Monolithic_kernel "Monolithic kernel") like most general-purpose operating systems are still vulnerable if any part of the kernel is compromised. A more secure design features [microkernels](/wiki/Microkernel "Microkernel") that separate the kernel's privileges into many separate security domains and reduce the consequences of a single kernel breach.[[118]](#cite_note-FOOTNOTETanenbaumBos2023612-123) [Unikernels](/wiki/Unikernel "Unikernel") are another approach that improves security by minimizing the kernel and separating out other operating systems functionality by application.[[118]](#cite_note-FOOTNOTETanenbaumBos2023612-123)

Most operating systems are written in [C](/wiki/C_(programming_language) "C (programming language)") or [C++](/wiki/C%2B%2B "C++"), which create potential vulnerabilities for exploitation. Despite attempts to protect against them, vulnerabilities are caused by [buffer overflow](/wiki/Buffer_overflow "Buffer overflow") attacks, which are enabled by the lack of [bounds checking](/wiki/Bounds_checking "Bounds checking").[[119]](#cite_note-FOOTNOTETanenbaumBos2023648,_657-124) Hardware vulnerabilities, some of them [caused by CPU optimizations](/wiki/Speculative_execution_CPU_vulnerabilities "Speculative execution CPU vulnerabilities"), can also be used to compromise the operating system.[[120]](#cite_note-FOOTNOTETanenbaumBos2023668–669,_674-125) There are known instances of operating system programmers deliberately implanting vulnerabilities, such as [back doors](/wiki/Backdoor_(computing) "Backdoor (computing)").[[121]](#cite_note-FOOTNOTETanenbaumBos2023679–680-126)

Operating systems security is hampered by their increasing complexity and the resulting inevitability of bugs.[[122]](#cite_note-FOOTNOTETanenbaumBos2023605,_617–618-127) Because [formal verification](/wiki/Formal_verification "Formal verification") of operating systems may not be feasible, developers use operating system [hardening](/wiki/Hardening_(computing) "Hardening (computing)") to reduce vulnerabilities,[[123]](#cite_note-FOOTNOTETanenbaumBos2023681–682-128) e.g. [address space layout randomization](/wiki/Address_space_layout_randomization "Address space layout randomization"), [control-flow integrity](/wiki/Control-flow_integrity "Control-flow integrity"),[[124]](#cite_note-FOOTNOTETanenbaumBos2023683-129) [access restrictions](/wiki/Access-control_list "Access-control list"),[[125]](#cite_note-FOOTNOTETanenbaumBos2023685-130) and other techniques.[[126]](#cite_note-FOOTNOTETanenbaumBos2023689-131) There are no restrictions on who can contribute code to open source operating systems; such operating systems have transparent change histories and distributed governance structures.[[127]](#cite_note-FOOTNOTERichetBouaynaya202392-132) Open source developers strive to work collaboratively to find and eliminate security vulnerabilities, using [code review](/wiki/Code_review "Code review") and [type checking](/wiki/Type_checking "Type checking") to expunge malicious code.[[128]](#cite_note-FOOTNOTERichetBouaynaya202392–93-133)[[129]](#cite_note-FOOTNOTEBerntssoStrandénWarg2017130–131-134) [Andrew S. Tanenbaum](/wiki/Andrew_S._Tanenbaum "Andrew S. Tanenbaum") advises releasing the [source code](/wiki/Source_code "Source code") of all operating systems, arguing that it prevents developers from placing trust in secrecy and thus relying on the unreliable practice of [security by obscurity](/wiki/Security_by_obscurity "Security by obscurity").[[130]](#cite_note-FOOTNOTETanenbaumBos2023611-135)

### User interface

Main article: [Operating system user interface](/wiki/Shell_(computing) "Shell (computing)")

A [user interface](/wiki/User_interface "User interface") (UI) is essential to support human interaction with a computer. The two most common user interface types for any computer are

- [command-line interface](/wiki/Command-line_interface "Command-line interface"), where computer commands are typed, line-by-line,
- [graphical user interface](/wiki/Graphical_user_interface "Graphical user interface") (GUI) using a visual environment, most commonly a combination of the window, icon, menu, and pointer elements, also known as [WIMP](/wiki/WIMP_(computing) "WIMP (computing)").

For personal computers, including [smartphones](/wiki/Smartphone "Smartphone") and [tablet computers](/wiki/Tablet_computer "Tablet computer"), and for [workstations](/wiki/Workstation "Workstation"), user input is typically from a combination of [keyboard](/wiki/Keyboard_technology "Keyboard technology"), [mouse](/wiki/Mouse_(computing) "Mouse (computing)"), and [trackpad](/wiki/Trackpad "Trackpad") or [touchscreen](/wiki/Touchscreen "Touchscreen"), all of which are connected to the operating system with specialized software.[[131]](#cite_note-FOOTNOTETanenbaumBos2023396,_402-136) Personal computer users who are not software developers or coders often prefer GUIs for both input and output; GUIs are supported by most personal computers.[[132]](#cite_note-FOOTNOTETanenbaumBos2023395,_408-137) The software to support GUIs is more complex than a command line for input and plain text output. Plain text output is often preferred by programmers, and is easy to support.[[133]](#cite_note-FOOTNOTETanenbaumBos2023402-138)

## Operating system development as a hobby

Main article: [Hobbyist operating system](/wiki/Hobbyist_operating_system "Hobbyist operating system")

A hobby operating system may be classified as one whose code has not been directly derived from an existing operating system, and has few users and active developers.[[134]](#cite_note-139)

In some cases, hobby development is in support of a "[homebrew](/wiki/Homebrew_Computer_Club "Homebrew Computer Club")" computing device, for example, a simple [single-board computer](/wiki/Single-board_computer "Single-board computer") powered by a [6502 microprocessor](/wiki/MOS_Technology_6502 "MOS Technology 6502"). Or, development may be for an architecture already in widespread use. Operating system development may come from entirely new concepts, or may commence by modeling an existing operating system. In either case, the hobbyist is her/his own developer, or may interact with a small and sometimes unstructured group of individuals who have like interests.

Examples of hobby operating systems include [Syllable](/wiki/Syllable_Desktop "Syllable Desktop") and [TempleOS](/wiki/TempleOS "TempleOS").

## Diversity of operating systems and portability

If an application is written for use on a specific operating system, and is [ported](/wiki/Ported "Ported") to another OS, the functionality required by that application may be implemented differently by that OS (the names of functions, meaning of arguments, etc.) requiring the application to be adapted, changed, or otherwise [maintained](/wiki/Software_maintenance "Software maintenance").

This cost in supporting operating systems diversity can be avoided by instead writing applications for [software platforms](/wiki/Software_platform "Software platform") such as [Java](/wiki/Java_(software_platform) "Java (software platform)") or [Qt](/wiki/Qt_(software) "Qt (software)"). These abstractions have already borne the cost of adaptation to specific operating systems and their [system libraries](/wiki/System_library "System library").

Another approach is for operating system vendors to adopt standards. For example, [POSIX](/wiki/POSIX "POSIX") and [OS abstraction layers](/wiki/Operating_system_abstraction_layer "Operating system abstraction layer") provide commonalities that reduce porting costs.

### Linux

Main article: [Linux](/wiki/Linux "Linux")

[![Image](//upload.wikimedia.org/wikipedia/commons/thumb/d/d4/Layers_of_a_Linux_system.png/500px-Layers_of_a_Linux_system.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](/wiki/File:Layers_of_a_Linux_system.png)

[Layers](/wiki/Abstraction_layer "Abstraction layer") of a Linux system

[Linux](/wiki/Linux "Linux") is [free software](/wiki/Free_software "Free software") distributed under the [GNU General Public License](/wiki/GNU_General_Public_License "GNU General Public License") (GPL), which means that all of its derivatives are legally required to release their [source code](/wiki/Source_code "Source code").[[135]](#cite_note-FOOTNOTESilberschatz_et_al.2018779–780-140) Linux was designed by programmers for their own use, thus emphasizing simplicity and consistency, with a small number of basic elements that can be combined in nearly unlimited ways, and avoiding redundancy.[[136]](#cite_note-FOOTNOTETanenbaumBos2023713–714-141)

Its design is similar to other UNIX systems not using a [microkernel](/wiki/Microkernel "Microkernel").[[137]](#cite_note-FOOTNOTESilberschatz_et_al.2018780-142) It is written in [C](/wiki/C_(programming_language) "C (programming language)")[[138]](#cite_note-143) and uses [UNIX System V](/wiki/UNIX_System_V "UNIX System V") syntax, but also supports [BSD](/wiki/BSD "BSD") syntax. Linux supports standard UNIX networking features, as well as the full suite of UNIX tools, while [supporting multiple users](/wiki/Multiuser "Multiuser") and employing [preemptive multitasking](/wiki/Preemptive_multitasking "Preemptive multitasking"). Initially of a minimalist design, Linux is a flexible system that can work in under 16 [MB](/wiki/Megabytes "Megabytes") of [RAM](/wiki/RAM "RAM"), but still is used on large [multiprocessor](/wiki/Multiprocessor "Multiprocessor") systems.[[137]](#cite_note-FOOTNOTESilberschatz_et_al.2018780-142) Similar to other UNIX systems, Linux [distributions](/wiki/Linux_distribution "Linux distribution") are composed of a [kernel](/wiki/Linux_kernel "Linux kernel"), [system libraries](/wiki/System_library "System library"), and [system utilities](/wiki/System_utilities "System utilities").[[139]](#cite_note-FOOTNOTESilberschatz_et_al.2018781-144) Linux has a [graphical user interface](/wiki/Graphical_user_interface "Graphical user interface") (GUI) with a desktop, folder and file icons, as well as the option to access the operating system via a [command line](/wiki/Command_line "Command line").[[140]](#cite_note-FOOTNOTETanenbaumBos2023715–716-145)

[Android](/wiki/Android_(operating_system) "Android (operating system)") is a partially open-source operating system closely based on Linux and has become the most widely used operating system by users, due to its popularity on [smartphones](/wiki/Smartphones "Smartphones") and, to a lesser extent, [embedded systems](/wiki/Embedded_system "Embedded system") needing a GUI, such as "[smart watches](/wiki/Smart_watch "Smart watch"), [automotive dashboards](/wiki/Android_Automotive "Android Automotive"), airplane seatbacks, [medical devices](/wiki/Medical_devices "Medical devices"), and [home appliances](/wiki/Home_appliance "Home appliance")".[[141]](#cite_note-FOOTNOTETanenbaumBos2023793–794-146) Unlike Linux, much of Android is written in [Java](/wiki/Java_(programming_language) "Java (programming language)") and uses [object-oriented design](/wiki/Object-oriented_design "Object-oriented design").[[142]](#cite_note-FOOTNOTETanenbaumBos2023793-147)

### Microsoft Windows

Main article: [Microsoft Windows](/wiki/Microsoft_Windows "Microsoft Windows")

[![Image](//upload.wikimedia.org/wikipedia/commons/thumb/d/db/Diagram_of_a_security_descriptor_for_a_file_on_Windows.png/330px-Diagram_of_a_security_descriptor_for_a_file_on_Windows.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](/wiki/File:Diagram_of_a_security_descriptor_for_a_file_on_Windows.png)

Security descriptor for a file that is read-only by default, specified no access for Elvis, read/write access for Cathy, and full access for Ida, the owner of the file[[143]](#cite_note-FOOTNOTETanenbaumBos20231021–1022-148)

Windows is a [proprietary](/wiki/Proprietary "Proprietary") operating system that is widely used on desktop computers, laptops, tablets, phones, [workstations](/wiki/Workstation "Workstation"), [enterprise servers](/wiki/Enterprise_server "Enterprise server"), and [Xbox](/wiki/Xbox "Xbox") consoles.[[144]](#cite_note-FOOTNOTETanenbaumBos2023871-149) The operating system was designed for "security, reliability, compatibility, high performance, extensibility, portability, and international support"—later on, [energy efficiency](/w/index.php?title=Energy_efficiency_in_operating_systems&action=edit&redlink=1 "Energy efficiency in operating systems (page does not exist)") and support for [dynamic devices](/w/index.php?title=Dynamic_device&action=edit&redlink=1 "Dynamic device (page does not exist)") also became priorities.[[145]](#cite_note-FOOTNOTESilberschatz_et_al.2018826-150)

[Windows Executive](/wiki/Windows_Executive "Windows Executive") works via [kernel-mode objects](/wiki/Object_Manager_(Windows) "Object Manager (Windows)") for important data structures like processes, threads, and sections (memory objects, for example files).[[146]](#cite_note-FOOTNOTETanenbaumBos20231035-151) The operating system supports [demand paging](/wiki/Demand_paging "Demand paging") of [virtual memory](/wiki/Virtual_memory "Virtual memory"), which speeds up I/O for many applications. I/O [device drivers](/wiki/Device_drivers "Device drivers") use the [Windows Driver Model](/wiki/Windows_Driver_Model "Windows Driver Model").[[146]](#cite_note-FOOTNOTETanenbaumBos20231035-151) The [NTFS](/wiki/NTFS "NTFS") file system has a master table and each file is represented as a [record](/wiki/Record_(computer_science) "Record (computer science)") with [metadata](/wiki/Metadata "Metadata").[[147]](#cite_note-FOOTNOTETanenbaumBos20231036-152) The scheduling includes [preemptive multitasking](/wiki/Preemptive_multitasking "Preemptive multitasking").[[148]](#cite_note-FOOTNOTESilberschatz_et_al.2018821-153) Windows has many security features;[[149]](#cite_note-FOOTNOTESilberschatz_et_al.2018827-154) especially important are the use of [access-control lists](/wiki/Access-control_list "Access-control list") and [integrity levels](/wiki/Safety_integrity_level "Safety integrity level"). Every process has an authentication token and each object is given a security descriptor. Later releases have added even more security features.[[147]](#cite_note-FOOTNOTETanenbaumBos20231036-152)
