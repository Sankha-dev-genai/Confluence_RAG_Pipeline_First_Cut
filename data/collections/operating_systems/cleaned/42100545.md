## A

- **[access token](/wiki/Access_token "Access token")**: In [Microsoft Windows](/wiki/Microsoft_Windows "Microsoft Windows") [operating systems](/wiki/Operating_system "Operating system"), an **access token** contains the security credentials for a [login session](/wiki/Login_session "Login session") and identifies the [user](/wiki/User_(computing) "User (computing)"), the user's groups, the user's privileges, and, in some cases, a particular application.

## B

- **binary semaphore**: See *semaphore*.
- **[booting](/wiki/Booting "Booting")**: In [computing](/wiki/Computing "Computing"), **booting** (also known as **booting up**) is the initial set of operations that a [computer](/wiki/Computer "Computer") performs after electrical power is switched on or when the computer is reset. This can take tens of seconds and typically involves performing a [power-on self-test](/wiki/Power-on_self-test "Power-on self-test"), locating and initializing peripheral devices, and then finding, loading and starting the [operating system](/wiki/Operating_system "Operating system").

## C

- **[cache](/wiki/Cache_(computing) "Cache (computing)")**: In [computer science](/wiki/Computer_science "Computer science"), a **cache** is a component that transparently stores data so that future requests for that data can be served faster. The data that is stored within a cache might be values that have been computed earlier or duplicates of original values that are stored elsewhere.
- **[cloud](/wiki/Cloud_computing "Cloud computing")**: Cloud computing operating systems are recent, and were not mentioned in Gagne's 8th Edition (2009).[[3]](#cite_note-Operating_Sytems_Concepts-3) In contrast, by Gagne's 9th (2012), cloud o/s received 3 pages of coverage (41, 42, 716). Doeppner (2011) mentions them (p. 3), but only to prove that operating systems "are not a solved problem" and that even if the day of the dedicated PC is waning, cloud computing has created an entirely new opportunity for o/s development ala sharing, networks, memory, parallelism, etc. Gagne (2012) adds that in addition to numerous traditional o/s's at cloud warehouses, [Virtual machine](/wiki/Virtual_machine "Virtual machine") o/s (VMMs), [Eucalyptus](/wiki/Eucalyptus_(software) "Eucalyptus (software)"), Vware, [vCloud](/wiki/VCloud "VCloud") Director and others are being developed specifically for cloud management with numerous traditional o/s features (security, threads, file and memory management, guis, etc.) (p. 42). Microsoft's investment in cloud aspects of o/s tend to support that argument.[[4]](#cite_note-:0-4)
- **[concurrency](/wiki/Concurrency_(computer_science) "Concurrency (computer science)")**

## D

- **[daemon](/wiki/Daemon_(computing) "Daemon (computing)")**: Operating systems often start daemons at [boot](/wiki/Booting "Booting") time and serve the function of responding to network requests, hardware activity, or other programs by performing some task. Daemons can also configure hardware (like [udevd](/wiki/Udev "Udev") on some [Linux](/wiki/Linux "Linux") systems), run scheduled tasks (like [cron](/wiki/Cron "Cron")), and perform a variety of other tasks.

## K

- **[kernel](/wiki/Kernel_(operating_system) "Kernel (operating system)")**: In [computing](/wiki/Computing "Computing"), the **kernel** is a [computer program](/wiki/Computer_program "Computer program") that manages [input/output](/wiki/Input/output "Input/output") requests from [software](/wiki/Software "Software") and translates them into [data processing](/wiki/Data_processing "Data processing") instructions for the [central processing unit](/wiki/Central_processing_unit "Central processing unit") and other [electronic components](/wiki/Electronic_component "Electronic component") of a [computer](/wiki/Computer "Computer"). The kernel is a fundamental part of a modern computer's [operating system](/wiki/Operating_system "Operating system").

## L

- **[lock](/wiki/Lock_(computer_science) "Lock (computer science)")**: In [computer science](/wiki/Computer_science "Computer science"), a **lock** or **mutex** (from [mutual exclusion](/wiki/Mutual_exclusion "Mutual exclusion")) is a [synchronization](/wiki/Synchronization_(computer_science) "Synchronization (computer science)") mechanism for enforcing limits on access to a resource in an environment where there are many [threads of execution](/wiki/Thread_(computer_science) "Thread (computer science)"). A lock is designed to enforce a [mutual exclusion](/wiki/Mutual_exclusion "Mutual exclusion") [concurrency control](/wiki/Concurrency_control "Concurrency control") policy.

## M

- **[mutual exclusion](/wiki/Mutual_exclusion "Mutual exclusion")**: Mutual exclusion is to allow only one process at a time to access the same critical section (a part of code which accesses the critical resource). This helps prevent [race conditions](/wiki/Race_condition "Race condition").
- **mutex**: See *lock*.

## S

- **[semaphore](/wiki/Semaphore_(programming) "Semaphore (programming)")**: In computer science, particularly in operating systems, a **semaphore** is a [variable](/wiki/Variable_(computer_science) "Variable (computer science)") or [abstract data type](/wiki/Abstract_data_type "Abstract data type") that is used for controlling access, by multiple [processes](/wiki/Process_(computing) "Process (computing)"), to a common resource in a [parallel programming](/wiki/Parallel_computing "Parallel computing") or a [multi user](/wiki/Multi-user_software "Multi-user software") environment.

## T

- **[thread](/wiki/Thread_(computing) "Thread (computing)")**: In [computer science](/wiki/Computer_science "Computer science"), a **thread** of execution is the smallest sequence of programmed instructions that can be managed independently by an [operating system](/wiki/Operating_system "Operating system") [scheduler](/wiki/Scheduling_(computing) "Scheduling (computing)"). The scheduler itself is a [light-weight process](/wiki/Light-weight_process "Light-weight process"). The implementation of threads and [processes](/wiki/Process_(computing) "Process (computing)") differs from one [operating system](/wiki/Operating_system "Operating system") to another, but in most cases, a thread is contained inside a process.
- **templating**: In an o/s context, templating refers to creating a single virtual machine image as a guest operating system, then saving it as a tool for multiple running virtual machines (Gagne, 2012, p. 716). The technique is used both in virtualization and cloud computing management, and is common in large server warehouses.
