Computer without an operating system

"Bare metal" redirects here. For other uses, see [Bare metal (disambiguation)](/wiki/Bare_metal_(disambiguation) "Bare metal (disambiguation)").

Not to be confused with [Bare-metal server](/wiki/Bare-metal_server "Bare-metal server").

In [information technology](/wiki/Information_technology "Information technology"), a **bare machine** (or **bare-metal computer**) is a [computer](/wiki/Computer "Computer") which has no [operating system](/wiki/Operating_system "Operating system").[[1]](#cite_note-databank-1) The software executed by a bare machine, a [standalone program](/wiki/Standalone_program "Standalone program") commonly called a *bare metal program* or *bare metal application*,[[2]](#cite_note-2) is designed to interact directly with hardware. Bare machines are widely used in [embedded systems](/wiki/Embedded_system "Embedded system"), particularly in cases where resources are limited or high performance is required.[[3]](#cite_note-3)

## Bare machine computing

**Bare Machine Computing** is a computing paradigm in which application software runs directly on a bare machine as a single, stand-alone executable, without an operating system or device drivers. The application software has direct access to hardware resources, and there is typically no distinction between user and kernel mode. It is self-managed software that boots, loads and runs without using any other software components. Bare metal programs are typically written in a close-to-hardware language such as [C](/wiki/C_(programming_language) "C (programming language)") or [assembly language](/wiki/Assembly_language "Assembly language").[[4]](#cite_note-4)

## Advantages

Typically, a bare-metal application will run faster, use less memory and be more power efficient than an equivalent program that relies on an operating system, due to the inherent overhead imposed by [system calls](/wiki/System_call "System call"). For example, hardware inputs and outputs are directly accessible to bare metal software, whereas they must usually be accessed through system calls when using an OS.[[5]](#cite_note-5) It has no OS and therefore has no OS-related vulnerabilities.

## Disadvantages

Bare metal applications typically require more effort to develop because operating system services such as memory management and task scheduling are not available.

Debugging a bare-metal program may be complicated by factors such as:

- Lack of a standard output.
- The target machine may differ from the hardware used for program development (e.g., [emulator](/wiki/Emulator "Emulator"), simulator). This forces setting up a way to load the bare-metal program onto the target ([flashing](/wiki/Firmware#Flashing "Firmware")), start the program execution and access the target resources.

## Examples

### Early computers

Early computers, such as the [PDP-11](/wiki/PDP-11 "PDP-11"), allowed programmers to load a program, supplied in [machine code](/wiki/Machine_code "Machine code"), to [RAM](/wiki/RAM "RAM"). The resulting operation of the program could be monitored by [lights](/wiki/Blinkenlights "Blinkenlights"), and output derived from [magnetic tape](/wiki/Magnetic_tape "Magnetic tape"), print devices, or [storage](/wiki/Computer_data_storage "Computer data storage").

### Embedded systems

[![Wikibooks logo](//upload.wikimedia.org/wikipedia/commons/thumb/f/fa/Wikibooks-logo.svg/40px-Wikibooks-logo.svg.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](/wiki/File:Wikibooks-logo.svg)

The Wikibook *[Embedded Systems](https://en.wikibooks.org/wiki/Embedded_Systems "wikibooks:Embedded Systems")* has a page on the topic of: ***[Super Loop Architecture](https://en.wikibooks.org/wiki/Embedded_Systems/Super_Loop_Architecture "wikibooks:Embedded Systems/Super Loop Architecture")***

Bare machine programming is a common practice in [embedded systems](/wiki/Embedded_system "Embedded system"), in which [microcontrollers](/wiki/Microcontroller "Microcontroller") or [microprocessors](/wiki/Microprocessor "Microprocessor") boot directly into monolithic, single-purpose software without loading an operating system. Such [embedded software](/wiki/Embedded_software "Embedded software") can vary in structure. For example, one such program paradigm, known as *foreground-background* or **superloop** architecture, consists of an infinite [main loop](/wiki/Main_loop "Main loop") in which each task is executed sequentially and must [voluntarily return control back to the loop](/wiki/Cooperative_multitasking "Cooperative multitasking").[[6]](#cite_note-6) The loop runs these cooperative *background* processes that are not time-critical, while [interrupt service routines](/wiki/Interrupt_service_routine "Interrupt service routine") momentarily interrupt the loop to handle time-critical foreground tasks.[[7]](#cite_note-7)
