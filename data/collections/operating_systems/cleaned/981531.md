These tables provide a **comparison of operating systems**, of computer devices, as listing general and technical information for a number of widely used and currently available [PC](/wiki/Personal_computer "Personal computer") or handheld (including [smartphone](/wiki/Smartphone "Smartphone") and [tablet computer](/wiki/Tablet_computer "Tablet computer")) [operating systems](/wiki/Operating_system "Operating system"). The article "[Usage share of operating systems](/wiki/Usage_share_of_operating_systems "Usage share of operating systems")" provides a broader, and more general, comparison of operating systems that includes [servers](/wiki/Server_(computing) "Server (computing)"), [mainframes](/wiki/Mainframe_computer "Mainframe computer") and [supercomputers](/wiki/Supercomputer "Supercomputer").

Because of the large number and variety of available [Linux distributions](/wiki/Linux_distribution "Linux distribution"), they are all grouped under a single entry; see [comparison of Linux distributions](/wiki/Comparison_of_Linux_distributions "Comparison of Linux distributions") for a detailed comparison. There is also a variety of BSD and DOS operating systems, covered in [comparison of BSD operating systems](/wiki/Comparison_of_BSD_operating_systems "Comparison of BSD operating systems") and [comparison of DOS operating systems](/wiki/Comparison_of_DOS_operating_systems "Comparison of DOS operating systems").

## Nomenclature

The nomenclature for operating systems varies among providers and sometimes within providers.
For purposes of this article the terms used are;

kernel
:   In some operating systems, the OS is split into a low level region called the kernel and higher level code that relies on the kernel. Typically the kernel implements processes but its code does not run as part of a process.[*[disputed](/wiki/Wikipedia:Disputed_statement "Wikipedia:Disputed statement") – [discuss](/wiki/Talk:Comparison_of_operating_systems#Proposed_nomenclature_section "Talk:Comparison of operating systems")*]

    hybrid kernel

    monolithic kernel

Nucleus
:   In some operating systems there is OS code permanently present in a contiguous region of memory addressable by unprivileged code; in IBM systems this is typically referred to as the nucleus. The nucleus typically contains both code that requires special privileges and code that can run in an unprivileged state. Typically some code in the nucleus runs in the context of a dispatching unit, e.g., address space, process, task, thread, while other code runs independent of any dispatching unit. In contemporary operating systems unprivileged applications cannot alter the nucleus.

License and pricing policies vary widely among different systems.
Among others, the tables below use the following terms:

[BSD](/wiki/BSD_licenses "BSD licenses")
:   **BSD licenses** are a family of [permissive free software licenses](/wiki/Permissive_free_software_license "Permissive free software license"), imposing minimal restrictions on the use and distribution of covered software.

bundled
:   The fee is included in the price of the hardware

3. ^ [***a***](#cite_ref-AmigaOSinstaller_18-0) [***b***](#cite_ref-AmigaOSinstaller_18-1) Amiga OS features since OS 2.0 version a standard centralized Install utility called [Installer](/wiki/AmigaOS#Workbench_2.0_user_interface_improvements "AmigaOS"), which could be used by any software house to install programs. It works as a [Lisp](/wiki/Lisp_(programming_language) "Lisp (programming language)") language interpreter, and install procedures could be listed as simple text. AmigaOS can also benefit from a 3rd party copyrighted library called [XAD](/wiki/XAD_(software) "XAD (software)") that is available for all POSIX ([Unix](/wiki/Unix "Unix"), [Linux](/wiki/Linux "Linux"), BSD, and for [AmigaOS](/wiki/AmigaOS "AmigaOS"), [MorphOS](/wiki/MorphOS "MorphOS"), etc.). This library is freely distributable and publicly available on [Aminet](/wiki/Aminet "Aminet") Amiga centralized repository of all Open Source or Free programs and utilities. XAD.Library, complete with GUI Voodoo-X, is based on modules and capable to manage over 300 compression methods and package systems (Voodoo-X GUI supports 80 package systems), including those widely accepted as standards such as [.ZIP](/wiki/ZIP_(file_format) "ZIP (file format)"), [.CAB](/wiki/Cabinet_(file_format) "Cabinet (file format)"), [.LHA](/wiki/LHA_(file_format) "LHA (file format)"), .[LZX](/wiki/LZX "LZX"), [.RPM](/wiki/RPM_Package_Manager "RPM Package Manager"), etc.
4. ^ [***a***](#cite_ref-AmigaOSinstallation_19-0) [***b***](#cite_ref-AmigaOSinstallation_19-1) A standard AmigaOS installation requires usually only few files (typically 3 to 10 files) to be copied in their appropriate directory, and libraries and language files for national localization to be put in their standard OS directories. Any Amiga user with some minimal experience knows where these files should be copied and could perform programs installations by hand.
5. **[^](#cite_ref-AmiUpdate_20-0)** AmiUpdate can update AmigaOS files and all Amiga programs which are registered to use the same update program that is standard for Amiga. Updating AmigaOS requires only few libraries to be put in standard OS location (for example all libraries are stored in `Libs:` standard virtual device and absolute path finder for `Libs` directory, Fonts are all in `Fonts:` absolute locator, the files for language localization are all stored in `Locale:` and so on). This leaves Amiga users with a minimal knowledge of the system almost free to perform by hand the update of the system files.
