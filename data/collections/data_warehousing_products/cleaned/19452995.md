**Exasol** is an analytics engine, an in-memory database company headquartered in Germany, EU. It supports a wide range of use cases, from standalone data warehouse deployments to analytics acceleration and AI/ML model enablement. Its technology is based on [in-memory](/wiki/In_memory_database "In memory database"), [column-oriented](/wiki/Column-oriented_DBMS "Column-oriented DBMS"), [relational database management systems](/wiki/Relational_database_management_systems "Relational database management systems").[[1]](#cite_note-DBMS2-1)

Since 2008, Exasol led the [Transaction Processing Performance Council](/wiki/Transaction_Processing_Performance_Council "Transaction Processing Performance Council")'s TPC-H benchmark for analytical scenarios, in all data volume-based categories 100 GB, 300 GB, 1 TB, 3 TB, 10 TB, 30 TB and 100 TB.[[2]](#cite_note-TPC-H_Website-2) Exasol holds the top position in absolute performance as well as price/performance.

## Products

Exasol is a parallelized [relational database management system](/wiki/Relational_database_management_system "Relational database management system") (RDBMS) which runs on a cluster of standard computer hardware servers. Following the [SPMD](/wiki/SPMD "SPMD") model, on each node the identical code is executed simultaneously. The data is stored in a column-oriented way and proprietary in-memory compression methods are used. The company claims that tuning efforts are not necessary since the database includes some kind of automatic self-optimization (like automatic indices, table statistics, and distributing of data).[[1]](#cite_note-DBMS2-1)

Exasol is designed to run [in memory](/wiki/In-memory_database "In-memory database"), although data is persistently stored on disk following the [ACID](/wiki/ACID "ACID") rules. Exasol supports the [SQL Standard 2003](/wiki/SQL:2003 "SQL:2003") via interfaces like [ODBC](/wiki/Open_Database_Connectivity "Open Database Connectivity"), [JDBC](/wiki/Java_Database_Connectivity "Java Database Connectivity") or [ADO.NET](/wiki/ADO.NET "ADO.NET"). A [software development kit](/wiki/Software_development_kit "Software development kit") (SDK) is provided for native integration.[[3]](#cite_note-InDetail-3) For [online analytical processing](/wiki/Online_analytical_processing "Online analytical processing") (OLAP) applications, the [Multidimensional Expressions](/wiki/Multidimensional_Expressions "Multidimensional Expressions") (MDX) extension of SQL is supported via [OLE DB for OLAP](/wiki/OLE_DB_for_OLAP "OLE DB for OLAP") and [XML for Analysis](/wiki/XML_for_Analysis "XML for Analysis").[[4]](#cite_note-4)

The license model is based on the allocated RAM for the database software (per GB RAM) and independent to the physical hardware. Customers gain the maximal performance if their compressed active data fits into that licensed RAM, but it can also be much larger.

Exasol has implemented a so-called cluster operating system (**EXACluster OS**). It is based on [Linux](/wiki/Linux "Linux") and provides a runtime environment and storage layer for the RDBMS, employing a proprietary, cluster-based file system (ExaStorage). Cluster management algorithms are provided like failover mechanisms or automatic cluster installation.[[1]](#cite_note-DBMS2-1)[[3]](#cite_note-InDetail-3)

In-database analytics is supported. Exasol integrates support to run [Lua](/wiki/Lua_(programming_language) "Lua (programming language)"), [Java](/wiki/Java_(programming_language) "Java (programming language)"), [Python](/wiki/Python_(programming_language) "Python (programming language)") and [GNU R](/wiki/R_(programming_language) "R (programming language)") scripts in parallel inside [user defined functions](/wiki/User-defined_function "User-defined function") (UDFs) within the DBMS' SQL pipeline.
